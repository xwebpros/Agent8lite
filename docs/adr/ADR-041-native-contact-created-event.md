# ADR-041 — Native contact-created reference event

Accepted by the coordinating owner on 2026-10-11 after verified ADR-040 implementation `d8529db`. This bounded M2 prerequisite closes the fresh Contact creation event gap recorded by ADR-040 and advances INV-03/INV-10. Commit the closed internal contract before producer and consumer changes. It adds no public API operation, generated API type, dependency, live provider or delivery behavior.

The frozen `packages/contracts/events.schema.json` catalog does not include `contact.created` and remains byte-for-byte unchanged. Define `packages/contracts/internal/native-contact-created-event-v1.schema.json` as the reviewed additive contract. The envelope is closed: `type=contact.created`, `version=1`, `producer=crm`, `aggregateType=contact`; UUID event/tenant/aggregate IDs; nonempty bounded correlation ID; database-clock `occurredAt` and `ingestedAt`; and payload exactly `{resourceId,resourceVersion}` with resourceId equal to aggregateId and resourceVersion exactly 1. It contains no name, channel, birthday, consent, request body, idempotency key, source row or other personal data.

Append exactly one validated event in the caller's PostgreSQL transaction after each fresh Contact row and channels are valid. Cover both published Contact POST and the existing internal `CrmService.create("contacts")` port used by reviewed CSV import. Historical receipt replay, changed/expired receipt rejection, duplicate-import skip and seed fixtures emit no event. The event helper rechecks actual runtime role, transaction tenant/actor, current membership/role/organization/full grants, contact-write authority, active CRM capability and the current version-1 unarchived Contact before insert. A failure rolls back Contact, channels, audit, receipt, event and any enclosing import work together. No event uniqueness migration or historical backfill is introduced in this slice; producer tests establish one event per newly allocated Contact UUID.

The existing synthetic reference outbox consumer authorizes Lead aggregates only. It must select only its approved `lead.captured`, `lead.assigned` and `lead.stage_changed` event types. `contact.created` remains committed and unpublished for a future scoped consumer, with no lease, attempt, receipt, audit or external delivery. This explicit selection prevents unsupported events from consuming bounded batches or starving approved Lead work. It does not claim a Contact consumer, campaign enrollment, message send or notification.

Backend owns the internal producer/helper and both Contact creation call sites under `apps/api/**`. Root owns the internal contract, contract checker and narrow worker selection. Tester owns actual PostgreSQL/runtime-role producer atomicity, import coverage, schema/privacy and unsupported-consumer fairness under `tests/**`. No migration or dependency file changes.

Acceptance proves closed-schema validation, aggregate/resource equality, database timestamps, one event for concurrent same-key Contact POST, one event for each distinct fresh command, one event for each accepted imported Contact, no event on replay/skip/rejection, transaction rollback of every effect, current authority/capability failure, no private payload values and no inherited serialization hook execution. Worker acceptance proves an older unsupported Contact event stays untouched while a later approved Lead event dispatches exactly once. Retain ADR-040 API/protocol/static tests, CRM/import/outbox/worker suites, types/contracts/format, production build and compiled runtime/launcher probes. Contact update/archive event completeness, real consumers, browser/device gates and full milestone completion remain separate.
