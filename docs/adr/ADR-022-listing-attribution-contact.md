# ADR-022 — Listing participant attribution contact

Accepted additive v1 contract correction on 2026-10-10 before consumers, following the owner's explicit instruction to include the [LVR IDX Listing Attribution Policy](https://members.lasvegasrealtor.com/news/article/idx-listing-attribution-policy). The notice requires the listing firm and its participant-provided email or phone beside the main listing information, in visible color/type at least as prominent as the medium listing text. The provider-selected contact comes from current MLS member information; an application's own agent/owner contact cannot substitute for it.

The original blueprint contract remains immutable. The exact reviewed amendment in packages/contracts/amendments/ADR-022-listing-attribution-contact.json adds only the optional nullable Attribution.contact property to the implementation v1 OpenAPI. A non-null value is a closed kind/value object (email or bounded phone). All existing required properties and request/response operations remain unchanged. This is additive for consumers that read the v1 projection; older records may lack the property. Contract verification derives the exact expected implementation from the original plus this named amendment and continues to reject all unrelated drift. Generated API types must precede consumers.

Canonical provider attribution may carry the corresponding optional contact. Unknown or denied field rights omit it in synthetic projection. Development fixtures use conspicuously fictional contacts and never send messages. UI consumers render escaped plain contact text beside the firm and primary price/facts, rather than assuming it is an inquiry destination. Live Trestle display requires licensed observed AttributionContact and ListOfficeName fields, permitted field mappings and valid nonempty firm/contact. Missing, malformed or unavailable required attribution suppresses the listing; no office/agent/owner fallback is guessed from unrelated fields. Current-member semantics, source freshness and revocation still require the approved resolver, independently of this projection support.

This correction does not activate the feed or establish current full MLS rules, logo/media/retention/alert/AI rights. The saved87-page rulebook is dated October2022, and its Coming Soon exclusion conflicts with the later official2026 bulletin. It is useful historical evidence rather than a complete current policy. Approved participant/site binding and all remaining M6 gates stay open. Existing logo and disclaimer fields remain; exact current assets/text/display requirements need their own verified policy evidence.

Acceptance covers amendment-only contract drift, closed email/phone shape and invalid values, generated types, source and field-right denial, no inferred contact fallback, escaped prominent list/detail presentation, and continued tenant/policy/withdrawal/expiry separation. Source/static tests do not establish browser or device accessibility.

The bounded phone pattern requires at least seven digits in the base number; extension digits cannot satisfy that minimum. This validation correction was verified against the exact amendment and generated types before consumer integration.

Coordinator-reviewed native seed fixtures grant attribution.contact and supply a reserved fictional email/phone only when inserting new synthetic feeds/listings. Existing ON CONFLICT DO NOTHING behavior remains: reseeding never alters existing rights, withdrawal, original ingestion/expiry or prior contact. Older interactive fixtures can therefore omit contact; they do not imply permission or valid live IDX attribution. Synthetic projection requires both current native and display field rights.
