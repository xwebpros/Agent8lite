# ADR-038 — Server contact name search and scoped pagination

Accepted by the coordinating owner on 2026-10-10 after verified reporting checkpoint0d7f6d1. This bounded M2 slice advances MOD-D-002 using frozen listContact, LeadFilter and PageContact. It adds no API shape, dependency, migration, provider or persistence. Commit shared prerequisites before consumers.

Replace Contacts' loaded-page name/email/phone filter with explicit server-backed name search. The existing q predicate is case-insensitive literal display-name containment, escaping SQL percent, underscore and backslash wildcards. Preserve the query exactly rather than silently trimming/changing it. An empty query omits q. Limit is25 per page, with a200-record private presentation bound and honest loaded/more/bounded labels. IDs sort ascending; this is neither chronological ranking, complete totals nor a transactionally stable multi-page snapshot. No email/phone search or saved-filter claim. Client query/results stay in private tab memory and do not enter application navigation URLs, browser history or persistent client storage. The approved bodyless GET necessarily carries its filter in the request URL; logging must omit/redact query values. This is not a claim that a server search transmits no query.

Current-member ownerMemberId is an additional filter for My workspace. All permitted records omits that selector and still intersects actual own/team/organization contact-read scope. Preserve existing contact/source archive and creator/lead ownership predicates; q is never permission evidence. Do not widen scopes, invent contact ownership, or count unfiltered loaded leads as complete opportunity totals. Actions open the existing contact route/drawer after synchronous current-context, loaded-result and shell draft/busy/unknown-command guards; the full detail API reauthorizes access.

Before this consumer, the contact-list path strictly projects a closed own-data query: cursor, limit and JSON filter only. Reject duplicate/array/object/coercive inputs, unknown keys and GET body/framing. HTTP scalar limit is canonical decimal1–100; service internal integer limit remains supported. Filter is bounded valid LeadFilter JSON and preserves implemented q/ownerMemberId/tagIds semantics; other existing unsupported filters remain rejected. Unicode maxLength follows the generated schema's200-codepoint limit; do not truncate names. Keep literal wildcard semantics and parameterization. No public sort selector.

The contact-list service independently binds verified runtime role, tenant/actor/member/role, current active organization/membership and actual contact grant, using a detached own-data authority projection and SHARE locks as in ADR037. Require current CRM capability within the service and recheck against database clock after waits/read before returning. Optional tag-source scope still requires actual corresponding read grants. Query and cursor serialization must not execute getters or inherited JSON hooks. Contact cursor bindings include current actor/org/member/role/full grants, filter and ID sort; a versioned internal contact binding may replace the old digest, making earlier cursors require a fresh search. Keep the existing signed, expiring opaque cursor envelope. No request tenant/owner identifiers prove authority.

Backend owns bounded contact-list changes in crm-service.ts and optional contact-query.ts; it may reuse/rename the detached reporting context helper and fixed primitive grant encoder without changing reporting behavior. Prefer a contact-specific safe binding over an unreviewed rewrite of the shared cursor protocol. Root owns main.ts body/framing boundary, status/runbook, shared prerequisites and integration. Frontend owns contacts-search-controller.ts, contacts-search.tsx, optional CSS and narrow Contacts panel/load-more/mount changes in workspace.tsx. Shared unfiltered dashboard data stays separate. Tester owns new contact-search actual API, pure/controller and static React tests. No owner edits another owner's files without coordination.

Integration review additionally allocates one narrow shared cursors.ts encodeCursor correction: encode the known primitive id/binding/expires envelope without inherited Object/Array.toJSON hooks, preserving property order, bytes, HMAC, signing-key lookup, expiry and decode protocol. Do not rewrite generic cursorBinding/decode behavior. Exercise an actual hasMore contact path in hook regression and retain touched pagination tests. Frozen normal arrays keep tagIds iteration usable; the contact binding's canonical serializer encodes only primitive leaves without object/array JSON hooks.

The controller binds user/org/member/access revision/permissions and explicit workspace scope. Changed query immediately hides previous results/cursors; submit reads the approved server predicate. Pagination cannot append a page from another query/context. Re-read accumulated pages from the start for refresh/load-more, through current authority, up to the200 bound; do not retain previously loaded pages as newly verified after a partial failure. Clear private query/results synchronously on offline/hidden/context cuts and discard late generations. Permission/capability denial clears data and cannot create an automatic retry loop; recovery requires a verified workspace refresh. Use generated PageContact validation, bounded detached response input and request timeout. No match, loading, partial, bounded, unavailable and ineligible/access-denied states differ. Focus return verifies current data; visible clock hides snapshots older than five minutes until explicit refresh. That expiry is a presentation limit, not a provider SLA.

Acceptance finds a name beyond the unfiltered first100; verifies literal wildcard/Unicode limits, no email/phone fallback, own/team/organization and tenant/archive intersection, cursor filter/current-grant binding, malformed/duplicate/body inputs, forged context/pool reuse and CRM expiry after real lock waits. Pure/controller/static tests prove bounded detached inputs, every UI state, exact requests, page/query/context races, refresh/failure/timeout, access/offline/hidden/focus cuts, freshness, privacy and guarded native contact actions. Root retains reporting/task/CRM checks in separate fixture-fresh batches, then types/contracts/format, production build and compiled launcher probes. Browser/axe/keyboard/device and full milestone gates remain open.
