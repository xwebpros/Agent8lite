# ADR-012 — Platform-owned content block registry

The2026-10-10 serializer repair uses bounded own-data descriptors and primitive-only serialization before parsing the detached tree. It rejects proxies before any trap, accessors, custom prototypes, sparse/extraneous arrays, hidden/symbol/non-JSON values, cycles and depth/node/UTF8 overflow. Object/Array prototype toJSON hooks are never invoked. Registry validators inspect own properties. This preserves supported rendering and bounded unsupported revision recovery without letting implicit JSON hooks replace content. Verification passes31/31 adversarial serializer cases,230/230 retained pure/template/CMS cases,61/61 actual-role CMS service cases and14/14 registered native API cases. The original implementation failed20 of the31 adversarial cases; the repair resolves them without weakening supported rendering or recovery behavior.

Accepted for local implementation on 2026-10-10. This establishes the first independent MOD-C-001/002/004 renderer contract, without enabling public sites or claiming M3 acceptance.

The frozen OpenAPI `RevisionWrite`, `Block` and `Seo` envelopes remain unchanged. API type generation uses `--empty-objects-unknown` because the four unconstrained object properties (block props, message designs and webhook data) permit JSON properties and cannot correctly be represented as `Record<string, never>`. Explicit closed request/response schemas remain closed. Runtime validation still supplies the boundary. `packages/templates/block-schema-v1.json` supplies the missing strict, versioned block-property schemas. Version 1 initially registers flat hero, text, CTA and footer blocks. Text uses plain paragraphs and explicit links rather than tenant HTML or executable CSS. Other specified block kinds remain recoverable editor data and cannot publish until their renderer, media rights, form or MLS capability checks exist.

Unknown document versions and unsupported blocks retain their original JSON for editor recovery. Safe editor warnings expose identifiers and issue codes, never execute tenant content. Publication fails closed on unsupported content, nested relationships, malformed properties, duplicate identifiers or unsafe links. Relative links stay on the verified site; external HTTPS links require an explicit approved origin. Canonical paths are local paths, never arbitrary remote URLs.

The renderer escapes all text and attribute values. No block triggers network requests, changes consent, creates a lead or publishes a revision. Puck will consume the platform-owned model through an adapter; the Puck component tree is not the persisted contract. Media, listings, maps, forms, domains, signed preview and transactional publication remain independent prerequisites.

Existing contract gaps remain explicit: `Block.type` currently enumerates known kinds, so a future unknown kind cannot be accepted by a frozen v1 API. Tolerant editor recovery applies to already stored or imported documents before boundary validation, not permission to add undocumented v1 kinds. A reviewed additive/new-version contract is required for a new block kind or an incompatible document migration.
