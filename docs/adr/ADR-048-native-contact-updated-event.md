# ADR-048 — Native contact-updated reference event

Accepted by the coordinating owner on 2026-10-11 after ADR-047. This bounded M2 slice closes the Contact update event gap recorded by ADR-039/041 and the milestone ledger, advancing INV-03/INV-10 and MOD-D-001. The internal contract is committed before its producer. It adds no public API operation, generated type, migration, dependency, consumer, provider or delivery behavior.

The frozen `packages/contracts/events.schema.json` catalog has `contact.archived` (produced by ADR-047) but no Contact update event, and it remains byte-for-byte unchanged. Define `packages/contracts/internal/native-contact-updated-event-v1.schema.json` as the reviewed additive contract. The closed envelope matches ADR-041: `type=contact.updated`, `version=1`, `producer=crm`, `aggregateType=contact`; UUID event, tenant and aggregate IDs; bounded correlation ID; database-clock `occurredAt` and `ingestedAt`. The payload is exactly `{resourceId,resourceVersion}`, where `resourceId` equals `aggregateId` and `resourceVersion` is the committed new Contact version (at least 2). The event carries no name, channel, birthday, consent, request body, idempotency key or changed-field list. Consumers must reload the Contact under current authorization.

The dedicated ADR-039 Contact PATCH boundary appends exactly one validated event in the same PostgreSQL transaction for each fresh committed revision. It is written after the compare-and-swap, channels and authorized projection, and before the audit and receipt. The event uses the command's database-clock instant, captured after all lock waits. Historical replay, a changed hash, an expired receipt, a stale revision, a validation failure and rollback emit nothing. The event, Contact, channels, audit and receipt commit or roll back together. Any authority or capability failure in the existing final rechecks also discards the event.

The existing reference outbox consumer continues to select only its approved `lead.captured`, `lead.assigned` and `lead.stage_changed` families. `contact.updated` stays committed and unpublished, with no lease, attempt, receipt or audit, for a future scoped consumer. Merge, consent and channel-verification events remain separate decisions.

Backend owns the producer under `apps/api/**`. Root owns the internal contract and its checker registration. Tester owns actual PostgreSQL/runtime-role atomicity, privacy, replay, concurrency and worker-fairness acceptance under `tests/**`. The retained Contact edit, Contact event, CRM, outbox, contracts, build and runtime gates must stay green.
