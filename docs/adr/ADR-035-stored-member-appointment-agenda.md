# ADR-035 — Stored member appointment agenda

Accepted by the coordinating owner on2026-10-10 after implementation resumed. This bounded working M2 slice advances MOD-B-001/004 through authenticated stored appointment reads and a mobile agenda. It does not implement or claim verified provider scheduling/cancellation, live calendar synchronization or their M4 acceptance. The frozen public contract has only GET /v1/orgs/{orgId}/appointments with cursor/limit and PageAppointment; it has no write, date-window, owner or scope parameters. Dashboard's body is unchanged. No dependency or published contract change is required.

AppointmentService in apps/api/src/appointment-service.ts exposes list(query): Promise<PageAppointment>, constructed inside the existing verified tenant transaction. Require current appointments.read with its catalog organization scope, current crm.leads.read and an enabled unexpired CRM entitlement. This route always narrows to lead.owner_member_id=current verified member, including organization grants, because default agent scope is normative and this contract has no explicit wider selector. Preserve the CRM team intersection: a team-only source grant additionally requires current shared-office membership, even for a self-owned lead. Both linked lead and contact must be unarchived. Existing organization-scope permission alone cannot grant another agent's appointment access.

Coordinator-owned SELECT-only SQL prerequisite precedes service execution. Keep existing tenant_scope and add restrictive runtime RLS checking actual session/current role, tenant/actor, current active organization/member/role, catalog grants, own lead/contact and current database-clock CRM entitlement. Grant only tenant_id,id,lead_id,starts_at,ends_at,timezone,state to estate_runtime; no provider/connection IDs, raw payload, INSERT/UPDATE/DELETE or worker/control access. No schema column or default seed change. Allocate forward0021 only after independent review. Service assertions cannot widen RLS; missing transaction context, forged contexts and pool reuse must be tested.

List accepts only scalar cursor/limit (default25, maximum100), rejects unknown/repeated/object/hooked fields, and uses existing signed opaque cursors bound to organization/actor/member/role/grants/resource/default-own scope. Sort by immutable appointment UUID ascending; pagination is over all currently authorized stored states, with no date window or total. Return only exact generated Appointment fields. Validate UUIDs, finite canonical UTC instants with end>start, supported named IANA timezone (UTC or slash-separated name/alias recognized by pinned Intl, maximum80), and scheduled/cancelled/completed state; invalid stored metadata is unavailable, never fabricated or reflected in errors. Database output emits UTC ISO timestamps. A fresh list may reflect changed assignment/archive/state; cursors are not snapshots or proof of a complete day.

Only linked lead/contact parents are SHARE-locked; appointment privileges remain SELECT-only. Recheck current authority and database-clock capability after lock waits and after reading. The final projection query is restricted to the initially selected appointment/lead pairs, so concurrent inserts or relinks cannot introduce an unlocked parent. A new refresh can discover those changed records. This is a bounded current read, not a provider snapshot or a booking guarantee.

AppointmentAgenda owns new appointment-agenda.tsx, appointment-agenda.module.css and appointment-controller.ts in apps/web/components, plus a narrow dashboard mount in workspace.tsx. Use generated types, props Session/memberId/online/accessRevision/onOpenLead/onAccessRevoked, memory-only bounded pagination, explicit refresh/load-more and disabled offline actions. Label records as stored/loaded, explain that calendar synchronization is not configured, and never infer next/today totals, booking success or integration readiness from an empty page. Include scheduled/cancelled/completed states. Display user and organization IANA labels when different, source timezone when different, and offset-aware start/end with UTC references so both DST-overlap occurrences remain distinguishable. Invalid user/org timezone is explicitly unavailable with a labeled UTC reference, not workstation-local fallback. Source-invalid metadata denies the page.

On offline/hidden/context/member/grant/access changes, immediately discard private rows/cursors and cancel or invalidate reads; late responses cannot refill them. Returning/focus starts a fresh current read. Current401/403 clears access and informs shell. Initial/current transient failure shows unavailable, not zero or complete; bounded loaded pages have an explicit incomplete/limit state. No private localStorage/IndexedDB/service-worker cache. Lead buttons must use the shell's synchronous dirty/uncertain-command guard and existing authorized lead drawer route; no direct unprotected link bypass.
