# ADR-026 — Native static message-design drafts and source history

Accepted bounded MOD-E-001 preparation on2026-10-10 after the reviewed W06 native-message-design-drafts proposal. This decision preserves the generated MessageDesignWrite, MessageDesign and PageMessageDesign contracts and their existing GET/list/POST/PATCH routes. It authorizes implementing a standalone native static-text editor and proposing additive storage before independent actual-role verification. It enables no route, SQL privilege, publication, campaign enrollment, scheduling or delivery by itself.

The server-only preparation module committed b488aed validates the exact closed schema-v1 text blocks, preserves optional subject, joins block text with LF exactly into content and snapshots canonical own data before any wait. Design, rendered content and its SHA256 are coupled. Names/subjects are single-line nonblank text when present; content can contain permitted newlines/tabs. Lone Unicode surrogates deny before hashing or PostgreSQL JSON storage; valid surrogate pairs and all supplied text remain unchanged. Markup, URLs, merge expressions, arbitrary templates and unlicensed editors remain unavailable. Browser consumers use the approved static schema and generated types without importing server crypto/util/Ajv modules.

## Immutable reference semantics

Message designs retain a stable aggregate UUID. POST creates ordinal1. PATCH requires current organization-scoped campaigns.write, enabled unexpired marketing capability, CSRF, Idempotency-Key and numeric strong If-Match. Channel/editor/identity cannot change. A successful edit advances design ordinal and SQL row_version together and appends an immutable snapshot of the locked aggregate. A referenced design is completely immutable: a first known rejection is409 design_referenced_immutable and authoring changed content requires explicit POST with a new aggregate UUID. A retry whose outcome is already uncertain preserves its original command/key/body and does not silently become a copy.

References include typed immutable workflow bindings and any preserved workflow definition, campaign step or scheduled action. Hidden published/history references count. A narrow fixed-search-path trigger may inspect hidden current-tenant reference existence, returning only a safe denial rather than IDs/content. New workflow creation captures an immutable design ordinal/hash binding under the same source SHARE lock used for current validation; PATCH takes UPDATE. Concurrent reference/update commands must either capture the authoritative current snapshot or reject an edit after the reference, never preserve incompatible meanings.

Existing historical content is not reconstructed from a current row. No permissive backfill assigns today's content to an old workflow. Legacy references without authoritative revision proof remain unresolved and unavailable. Rows inserted after the new boundary may append a truthful observed revision through the snapshot trigger, including explicitly authorized fixture inserts. Original stored rows are preserved; current source read/availability and history proof remain mandatory even when a reference exists. History does not authorize sending or bypass current source revocation.

## Storage and command prerequisites

The coordinator reviews and commits the exact candidate before probe/consumer work and allocates a forward migration only after its acceptance. Add bounded nullable subject, explicit draft availability, append-only message-design revisions and immutable tenant/workflow/node/source bindings. New tables require FORCE RLS, tenant-qualified foreign keys, bounded ordinals and minimal runtime grants. Replace0017's restrictive WITH CHECK(false) only through explicitly reviewed command-specific policies; keep source SHARE locks possible while granting only approved unreferenced draft changes. No worker/control/issuer write grant or runtime ownership is added.

Trigger functions qualify relations, pin pg_catalog search_path, revoke PUBLIC execution, verify actual runtime login and transaction tenant/actor, lock current membership/organization/grants/capability and recheck database time after waits. Snapshot insertion copies actual locked fields rather than caller-provided content. Hidden reference checks and positive integer exhaustion are explicit. Existing trigger/version behavior must be reconciled before application.

The reviewed storage candidate captures workflow bindings in a BEFORE trigger after the existing locked sequence allocator. PostgreSQL applies SELECT checks to INSERT RETURNING before the new workflow tuple exists. Only this pending insertion may use private parent/actor/xid8/exact-definition-hash provenance; runtime cannot select or write those columns. The deferred tenant-qualified workflow FK requires the captured workflow row at commit, and any later failure rolls back its bindings. Existing-row proof requires the exact stored graph and a currently readable draft parent/version. Current source proof couples every copied field and source_row_version, not only the body hash. This exception grants no history lookup, session flag or caller-supplied proof authority.

Commands run inside the caller-owned tenant transaction. Durable receipts bind tenant/actor/route/original canonical body/If-Match and retain the historical response and exact ETag. Replay reauthorizes current source access without presenting an old version as current. Design, immutable snapshot, audit, closed internal reference event and receipt commit together. List responses are complete bounded entities under the private1MiB transport limit; no truncation or private browser persistence. No undocumented history endpoint or handwritten HTTP contract is introduced.

The internal message_design.draft_changed v1 schema contains only opaque design ID, positive design ordinal and create/update operation. Event/outbox tenant/aggregate/actor/times derive from the verified transaction. No subject, name, body/design, destination or personal information enters events, logs or audit. The existing lead-only consumer defers this unknown family. Receipt/history storage is private and never placed in service-worker or IndexedDB caches.

Acceptance requires independent actual-role migration/RLS/grant/context probes, immutable snapshot coupling, hidden/unresolved reference denial, genuine SHARE-versus-UPDATE races, current DB-clock revocation/expiry after waits, atomic rollback, same-key concurrency/historical receipt conflicts, integer exhaustion and registered HTTP/private-response tests. Standalone source tests and51 pure preparation tests establish no storage, browser, send or fullM4 acceptance. Browser/physical-device verification remains a separate gate.
