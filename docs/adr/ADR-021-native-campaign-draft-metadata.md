# ADR-021 — Native campaign draft metadata prerequisite

Accepted bounded MOD-E-001/003 prerequisite on 2026-10-10 before consumers. The unchanged frozen Campaign, CampaignWrite and PageCampaign contracts define list/detail/create/update bodies. This slice exposes draft metadata only; workflow versions, publication, enrollment, schedules and delivery require their own reviewed implementations and acceptance gates.

An additive internal `native-campaign-draft-event-v1.schema.json` defines the closed `campaign.draft_metadata_changed` v1 envelope. Its payload contains campaignId, metadataRevision and create/update operation only. The marketing producer validates the schema and matching aggregate/tenant/actor context, uses database-clock timestamps and atomically commits the draft, event, audit and actor/tenant/operation/input-bound native command receipt. The frozen event catalog stays unchanged. The lead-only reference dispatcher defers this family until a reviewed consumer is explicitly registered; it cannot acknowledge an unknown event. Campaign names, message content and customer data stay out of event/audit safe fields.

Native metadata command receipts use expires_at=infinity and are read without an expiry filter. This prevents a later retry from creating a duplicate after a unique receipt key has aged out of an application lookup window. Replay reauthorizes the current member, permission, marketing capability and current draft, then returns the historical response and explicit strong numeric ETag without applying historical input. These durable native receipts do not establish any external provider idempotency guarantee. Receipt retention and deletion need an explicit future coordinated policy rather than accidental lookup expiry.

The reviewed W06 SQL candidate grants runtime SELECT and narrow INSERT/UPDATE columns on app.campaign. Restrictive SELECT/INSERT/UPDATE policies additionally require the verified tenant and draft state. State changes, campaign versions, enrollment, deletion, worker/control/issuer privileges and delivery authority are absent. Existing FORCE RLS and transaction-local verified context remain mandatory. Root promotes the candidate to forward migration0016 only after independent actual-login candidate probes pass; no database reset is authorized.

Services run inside the existing caller-owned tenant transaction. They require organization-scoped campaigns.read/write and a currently enabled, unexpired marketing capability, rechecked with the database clock after awaited locks. Current seed capability remains disabled. Only explicit disposable synthetic fixtures enable it during acceptance. Reads use signed expiring actor/member/tenant/current-grant-bound cursors and UUID keyset order, which is a live view rather than chronological order or a frozen audience preview. Strong revision preconditions, closed frozen schemas, private response headers, same-origin CSRF and durable idempotency apply at registration.

Acceptance must prove actual-role isolation and direct write denial, current permission/membership/capability and lock-wait expiry, concurrent identical commands, changed-input conflicts, historical replay after later edits, revision races, rollback of all durable references, safe cursors and truthful deferred dispatch. These prerequisites do not complete M4 or authorize an outbound message.
