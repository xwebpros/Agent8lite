# ADR-031 — GoDaddy Node.js proof-of-concept launch adapter

Accepted by the coordinating owner on2026-10-10 after the user explicitly requested a GoDaddy launch adapter, committing/pushing application code and merging main. Other agents remain paused. This authorizes bounded launch integration and local verification, not public synthetic identity, provider activation or an actual deployment.

Provide root npm-compatible build/start commands. Build uses the pinned local Node/TypeScript/Next executables without requiring a global pnpm binary. Move the existing exact build compiler/type packages needed during production-only installation into dependencies; keep the pnpm lockfile and all approved version pins. Do not depend on platform automatic package installation.

The root launcher supervises the compiled API and Next server as owned children. Next is the single public HTTP listener, bound to the assigned PORT. The API binds only127.0.0.1 on an ephemeral port and reports its ready port over the private parent-child IPC channel; the launcher sets the existing BFF API_ORIGIN to that exact endpoint. Never discover an unrelated listener or use an inherited API_HOST/API_ORIGIN as startup evidence. Require an explicitly configured non-owner DATABASE_URL; do not migrate, seed, use a migration identity, start workers or load secret files. The normal external worker boundary remains separate.

Force hosted launch to production mode with synthetic identity disabled in both children, regardless of inherited development flags. Pass database credentials only to the API, strip migration/control/issuer/provider credentials from the web environment, and preserve current membership/RLS/CSRF/no-delivery/MLS/cache boundaries. Production identity remains unconfigured and private routes deny it until its independently reviewed adapter exists. Root start is not a production-authentication implementation.

API IPC messages are additive private process control, not published API/event contracts: ready contains only a bounded loopback port; shutdown closes the owned application and runtime pools. Unexpected child failure stops the sibling and makes the parent fail. Signals and startup deadlines close only owned children, with bounded termination escalation. No detached/background services are created.

Verify root build, manifest integrity and real local compiled API/Next startup on a non-default assigned port using only fixed public loopback fixture runtime credentials. Verify production synthetic denial and owned child cleanup/failure. Source, contracts, relevant regressions and a clean dependency-only install must pass before the owner-authorized main integration. Actual GoDaddy runtime/child-process support, private PostgreSQL/PostGIS and real identity remain deployment prerequisites; no remote acceptance is claimed from local execution.
