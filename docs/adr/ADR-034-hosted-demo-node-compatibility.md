# ADR-034 — Hosted demo Node compatibility

Accepted by the coordinating W01/W11 owner on2026-10-10 after current GoDaddy logs prove the corrected production launcher is reached but fails launch_node_version_invalid. The host's exact Node version remains unknown. This is a bounded deployment fix, not a full SaaS runtime upgrade or release.

Keep .node-version (24.19.0) and CI as the authoritative full application/API/worker/toolchain pin. Declare the install compatibility envelope in package.json engines.node as >=22.13.0 <23 || >=24.0.0 <25. The existing pnpm11.25.0 itself requires Node>=22.13; pinned Next16.4.0 declares>=20.9. Only explicitly enabled HOSTED_DEMO_ENABLED=true may build and run the web-only preview on this bounded22/24 envelope. Full application launch, runtime artifact compile/verification and compiled API probes still require the exact pin. Never replace those checks with package.json's install range. Dependency versions, lockfile resolution, frozen contracts, RLS, identity, preview password/origin/cookie and no-delivery guards remain unchanged.

Shared internal policy is scripts/node-runtime.mjs: hostedDemoNodeRange, readPinnedNode(root), nodeRuntimeAllowed(version,pin,demo), assertNodeRuntime(version,pin,demo,code), and a NodeRuntimeError whose safe diagnostics contain only canonical actual Node version and required version/range. launchConfiguration(environment,workspace,nodeVersion=process.version,pinnedNode=workspace.engines.node) uses the policy; real start supplies the authoritative file pin explicitly. Invalid/old/odd/prerelease versions deny. Do not log arbitrary environment or exception text. Success logs also report actual Node.

Explicit demo build runs only Next (real SSR build), skips API/worker compilation, and reports demo mode. Full build still compiles the API/worker under the exact pin. Switching demo off requires a full rebuild on the approved pin and all original DB/identity prerequisites. Demo-only build must not certify or regenerate full runtime artifacts. Set the demo flag before hosting build and start, not merely after a failed launch.

Coordinator owns package metadata, pin readers, policy/build/start, docs/status and main integration. A bounded test/review owner may update scripts/launch.test.mjs after this declaration; another reviewer may inspect policy/guards read-only. No database migration or provider change is included. Verify canonical lower/upper version boundaries, rejection in full mode, safe logging and retained port/secrets/identity/child ownership tests. Execute real production-only demo builds and starts with a second24 patch and supported22 binary; do not claim actual-version compatibility from injected version strings alone. Current GoDaddy logs/URL/HTTPS and preview environment remain external acceptance evidence.
