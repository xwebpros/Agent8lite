# ADR-042 — Explicit local forgetting after command retry expiry

Accepted by the coordinating owner on 2026-10-11 after ADR-040 verification. This bounded client recovery decision supersedes only ADR-039/ADR-040 statements that an expired unknown command cannot be abandoned locally. It does not add a server outcome API, cancel a command, delete a record, renew an idempotency receipt or prove success/failure.

When an unknown Contact edit or Add lead step can no longer be resent because either conservative 23-hour clock expires or its wall/monotonic clock becomes invalid, offer one explicit action labelled **Clear this tab’s recovery data**. Explain before the action that the earlier command may or may not have completed, clearing does not cancel or undo it, and the user should review current records before attempting related work. Do not use Saved, Failed, Cancelled, Not applied or Resolved language.

The action sends zero requests. It synchronously invalidates the command generation and removes all retained bodies, keys, UUIDs, contact/lead values and drafts from protocol and workspace memory. A context-bound generic warning remains: an earlier command outcome is unconfirmed and its local recovery data was cleared. The warning contains no record identifiers or personal data. It releases dialog/drawer close, internal navigation, sign-out and PWA activation. It never copies values, automatically opens a form, chooses a new key or resubmits. A late response/callback cannot acknowledge, refresh or restore the forgotten command.

For the same verified context, the forgotten protocol refuses a new command through that recovery controller while its generic warning remains. A full verified context replacement or document reload creates a new controller lifetime; because no durable server outcome index exists, the application still cannot prevent a later human from creating a possible duplicate. The UI states this limit rather than claiming safety. Current read-only record review may continue through separately authorized reads and never establishes command identity from matching names/channels.

Frontend owns protocol/panel and narrow workspace guard changes under `apps/web/**`. Tester owns protocol/controller/static acceptance under `tests/**`. No API, schema, migration, service-worker storage, IndexedDB, URL/history value, dependency or provider changes. An authoritative outcome lookup remains a future reviewed public/internal contract: a missing receipt must stay unknown, and guaranteed nonexecution would require a durable key/hash tombstone checked under the same advisory lock by every supported mutation.

Acceptance covers exact retry expiry and invalid clocks, action absence while retry is available, zero network calls, synchronous private-data removal, generic-only rendering, new-command refusal in the same binding, navigation/update release, stale/late callback invalidation, context reset and no automatic replacement. Retain all ADR-039/040 command, lifecycle and private-withholding tests. Browser/axe/keyboard and physical installed-mode behavior remain open.
