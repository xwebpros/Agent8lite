# ADR-018 — Registered synthetic CMS, properties and staff workspaces

Accepted bounded integration on 2026-10-10 after actual-role module tests, registered API acceptance and source review. Frozen v1 bodies and generated contracts remain unchanged. This decision does not approve production identity, external effects, public publication or live Trestle.

The coordinator imported reviewed CMS checkpoints through `151b992` and property checkpoints through `eea4b49`, applying shared forward migrations0013/0014 after0012. Authenticated local site/document/revision commands and reads use the administration-owned same-transaction profile reference port. Draft saves use `/dev/orgs/:org/cms/documents/:document/drafts`, frozen RevisionWrite/Revision, mandatory If-Match/CSRF/idempotency and the original replay ETag. Unknown revisions require an authorized recovery contract; publication, rollback and the frozen revision-save mutation remain unavailable. Browser field editing is a bounded native draft slice; Puck and full M3 acceptance are still pending.

The Properties workspace uses only the authenticated synthetic MLS `/dev/` reads. Feed/connection/listing rows are locked and current rights, actual ingestion, withdrawal and capability expiry are rechecked with the current database clock. Seed uses only the reviewed mock replication adapter, never refreshes original fixture timestamps or overwrites revocation/withdrawal, and enables fixture capabilities only when absent. Private UI state stays in memory and clears on source errors, expiry, offline or context loss. A permission denial returns to a safe workspace view; it cannot trigger repeated immediate remounts and denied requests. Mobile navigation uses the same permission filter and accommodates the added view.

Separate `/dev/staff` web UI and `/dev/staff/session`, `/dev/staff/logout`, requester Job read/run and frozen platform organization list/create API routes require explicitly configured loopback control/issuer pools. The staff raw-stream adapter is registered before body parsers, retains bounded JSON, Origin/CSRF, safe Problems and current principal/session checks. Read/mutation rate buckets bind the verified staff user; unrelated cookies and another session for that principal cannot reset limits. Initial local sign-in uses a separate fixed-IP limit. Support selection/customer projection remains unavailable.

The same-origin BFF explicitly selects only `estate_staff_session` for `/dev/staff/*` and `/v1/platform/*`, or only `estate_session` for member paths. It rejects duplicate cookies in the chosen context and drops preference/opposite-identity cookies. This route selection supplies no authority: the API independently verifies the selected opaque session, current membership/principal, permission and CSRF. Direct API requests carrying both identity cookies fail closed. Browser staff state/CSRF is separate from member state; neither context creates a staff tenant Owner.

Provisioning run keys commit atomically with the claimed attempt before work. Replays resolve the current requester-authorized Job without claiming again, including after a claim/failure crash cut point. A deliberate new-key retry is distinct from uncertain transport replay. Defaults, activation, success, audit and outbox commit on one caller client; failed execution rolls back all defaults before a safe failure ledger. The staff UI rechecks current state before execution, confirms a new failed-attempt key explicitly, retains uncertain keys, and never infers claim expiry. The bootstrap outbox reference still requires its separate downstream recovery gate.

Dirty, pending and uncertain content protects navigation and service-worker reload. The Websites view uses the synchronous protection signal for main/mobile/brand/installation links and explicit organization changes/logout; the editor supplies deliberate discard and exact-key recovery. Same-context transient session reads preserve the bound editor. Explicit organization changes hide old private features and reconcile the current session before reporting success. CRM reads require the matching session permission, absent permissions show unavailable metrics, and an unrelated permission/capability denial arriving after a draft starts cannot invalidate its CMS binding. Definite identity/membership loss and unrecognized denial still invalidate access. The service worker caches only existing safe static assets/generic offline shell; no new private browser persistence is added. The staff page wires its recovery callback into an update guard. Editor/Property static rendering, bundle checks, TypeScript and builds do not establish real keyboard, reflow, axe or physical-device acceptance.

Executed gates: CMS26 actual-role cases, MLS17 actual-role cases plus177 pure/static cases, CMS42 editor/browser-adapter cases with a four-output in-memory bundle free of Node imports/globals, control20 actual-role cases including two durable crash cut points, registered native API8, registered staff API10 including session-expiry rollback and unchanged rate limits, and BFF21 source-handler cases. Combined acceptance is recorded separately in IMPLEMENTATION_STATUS.md. No milestone completion or release follows while its remaining gates are unverified.
