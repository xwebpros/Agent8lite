# ADR-037 — Default-member dashboard measurement

Accepted by the coordinating owner on 2026-10-10 after published task checkpoint42404c1. This bounded M2 slice advances MOD-B-001/002 using the frozen Dashboard, Metric and Period schemas. GET /v1/orgs/{orgId}/dashboard declares no query parameters or request body. Reject undeclared inputs; add no public selector, schema, migration, dependency or provider. Shared prerequisites are committed before consumers.

The approved leads.created definition version2 counts currently unarchived leads owned by the verified current member, intersected with the actor's actual current crm.leads.read grant. Unassigned, other-member and archived leads are excluded. Current reassignment/archive changes historical-period counts; this is current eligible inventory created in the period, not an immutable acquisition funnel. Preserve the existing CRM lead-read predicate rather than inventing contact-archive exclusions. Team grants additionally require existing permitted office relationships; lack of eligible rows is a legitimate measured zero. A missing/revoked grant or disabled/expired CRM capability is denied, not zero. Organization/team grants cannot widen the no-selector default. Source is crm-own-utc-month-query-v2; unit is leads; denominator is not relevant to this count. Revenue version1 remains null/unavailable with source billing-unconfigured and unit USD.

Use a captured PostgreSQL clock truncated to public millisecond precision before constructing and executing the closed from/to query. Period runs from current UTC calendar-month start through that same captured instant; Period.timezone is UTC. Use UTC calendar operations only, independent of server/device timezone. The returned bounds must exactly describe counted microsecond source timestamps. Record refreshedAt after measurement and recheck the current CRM capability against database time after waits. This is a measured source snapshot, not ongoing synchronization. Independently bind runtime/session identity, tenant/actor/member/role, active organization/membership and actual dashboard/lead grants under SHARE locks; stale or forged supplied context is not authority. Hold actor office links for team measurement and recheck scope after waits.

Backend owns the bounded existing crm-service.ts dashboard implementation and may add a pure dashboard-time.ts helper. Preserve the existing Dashboard task-source checks; its returned task rows default to current assignee, intersect actual task grant and remain bounded. If the member lacks task-read permission, a reporting-only request can return its measured lead metric with tasks empty; the report UI makes no task inventory claim from that array. Notifications/integrationHealth are unused by this bounded consumer and establish no synchronization claim. Root owns any main.ts request-boundary adjustment, frozen contracts, status and integration. Tester owns a new dashboard-report-api.test.ts and necessary pure/static reporting tests. No shared ownership/dependency change.

Frontend owns replacement verified-metrics.tsx, a bounded verified-metrics-controller.ts, optional reporting CSS and narrow workspace mount props. Bind private reads to verified user/org/member/access revision and current permission context, including organization switch, visibility and online state. Clear/hide private snapshots synchronously on context cuts; abort or discard late generations. Use bounded detached input and generated-schema validation. A static approved presentation catalog describes leads.created v2 and unavailable revenue v1; unknown definitions are explicitly unsupported. Available requires a valid finite measurement and valid measured refresh. Measured zero stays zero; loading, empty/no measurement and unavailable stay distinct. Contradictory null/value/freshness metadata cannot receive a positive available badge. Show definition/version, source, closed period, explicit UTC timezone/offset reference and measured refresh. User-local offset labels may supplement UTC when valid. This count has no denominator; do not invent a numerator/ratio contract field.

Use explicit client snapshot freshness: after five minutes without a new successful measurement, mark the report stale and withhold current numeric values until refreshed. This is a bounded presentation expiry, not a source/provider SLA. A visible clock reevaluates expiry; explicit refresh uses the same frozen read and current binding. No private persistence, new query scope, inferred engagement or provider status. Existing loaded-list summary cards are outside this reporting-only allocation; their separate loaded/partial labels are retained and their fuller state/freshness work remains open.

Acceptance covers UTC month boundaries independent of process timezone, exact millisecond query bounds, same-predicate source reconciliation, own/team/organization grant intersection, valid measured zero, other-tenant/archived/unassigned exclusions, source changes, missing grants, forged context, post-wait CRM expiry, exact request/response validation and retained task-source behavior. Pure/controller/static React tests cover approved/unsupported definitions, every state, contradictory metadata, offset/UTC labels, freshness expiry, timeout/failure, retry and late member/access/offline/hidden cuts. Root runs relevant retained tests, types/contracts/format, full build and compiled launcher probes. Browser/keyboard/axe/device and full milestone exit gates remain open; no milestone is completed by this slice.
