# ADR-039 — Contact drawer edit recovery

Accepted by the coordinating owner on 2026-10-10 after verified contact search checkpoint 25b1d2d. This bounded M2 slice advances MOD-D-001/007 and the MOD-K interrupted-command criterion using frozen updateContact, ContactWrite, Contact, Problem and strong revision headers. Commit these prerequisites before dependent implementation. No API shape, migration, dependency or provider is added.

The scope is the existing authenticated contact drawer PATCH, not Contact POST or the Add lead Contact POST → Lead POST chain. Those create/capture commands, other generic CRM mutations, merge/consent/archive/event-producer completeness and milestone exit gates remain unfinished. Preserve normalization, source scope, channel provenance and audit semantics. Do not invent a contact event type absent from the approved event catalog.

Before any await, capture a bounded, detached generated ContactWrite, original contact UUID, original positive safe revision, explicit printable UUID idempotency key and current verified command context. Bind user, organization, member, CSRF, access revision and current permissions. The body, revision and key cannot be rebuilt from subsequently edited fields. Unknown outcomes retain the exact command in private tab memory; explicit reconciliation sends that body/key/If-Match unchanged. Network, interrupted/malformed response and ambiguous server failures do not mean unsaved. A rejected reconciliation, including 409/412/429, cannot prove the earlier attempt failed. An initial definitive rejection may release the command for conflict/error review. Current identity/access loss invalidates callbacks and clears private command data.

The contact PATCH service independently validates detached authority and request input. Actual runtime role, transaction tenant/actor, current membership/role/organization, complete grants and current CRM capability are required. Intersect existing contact read and write predicates; wider read permission cannot authorize a narrower write. Preserve creator-with-no-active-lead and own/team/organization semantics without adding a new lead-read requirement. After advisory waits, lock the contact FOR UPDATE, every related lead (including archived rows that could reactivate) in stable ID order, and required actor/owner office links in stable order. The contact lock closes new-lead foreign-key insertion while held. Requery original scope/archive eligibility after all waits, recheck CRM with clock_timestamp, and recheck before returning after channels/projection/audit. Replay performs the same current-source/write checks before returning a historical receipt. Failed reauthorization rolls back contact/channel/audit/receipt effects.

Keep the existing actor/tenant/route/key and canonical input-hash protocol and one-day receipt duration. Only exact contact PATCH receipt lookup changes: after the advisory lock, inspect an existing ledger row regardless of expiry using current database time. Changed input remains 409; an expired matching receipt returns safe 409 receipt_expired, never falls through into a fresh mutation, and never renews the receipt. No receipt cleaner or generic idempotency rewrite is allocated here. The client permits explicit reconciliation only within a conservative 23-hour window from the original send, checked using both wall and monotonic elapsed time; invalid/backward clocks fail closed. Outside that window, stop resending and retain an unconfirmed state requiring current record review. Neither client nor server promises indefinite deduplication after future receipt deletion; any cleanup policy requires its own reviewed durable-key decision.

A successful command requires a bounded generated Contact and matching strong ETag, expected original-version-plus-one, same UUID and normalized submitted fields. Compare email/phone values as normalized unique sets, not request order: emails trim/lowercase, phones trim/remove spaces, parentheses, periods and hyphens, names trim. Only supplied optional fields are compared; canonical UUID spelling and null birthday handling follow the current model. The historical receipt acknowledges the command; it must not replace newer detail. Clear the command, then fetch authoritative current detail and refresh affected lists. If that read fails, show acknowledged save with current detail unavailable rather than apply stale receipt data or recreate the command.

Sending/unknown commands synchronously protect navigation, drawer close, organization switch, sign-out, new competing edits and PWA reload. Offline/hidden views withhold private draft/command details while preserving the pending command in memory; mutation is disabled. Retained callbacks check current binding, online/visibility and busy/draft guards before begin, retry, send or applying results. Use native accessible reconciliation controls and truthful sending, acknowledged, conflict, denied, unavailable, unknown and expired states. No service-worker, IndexedDB, navigation URL or persistent storage holds command bodies/keys.

Backend owns bounded crm-service.ts contact PATCH/receipt/authority changes and optional contact-command.ts. Frontend owns contact-edit protocol/presentation files and narrow workspace integration. Tester owns new contact-edit protocol/controller/static and actual PostgreSQL/runtime-role API tests. Root owns shared decisions, status/runbook, integration, builds and probes. Do not edit another owner's files or change shared contracts/dependencies/migrations without coordinating.
