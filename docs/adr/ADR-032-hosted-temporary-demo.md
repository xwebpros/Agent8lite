# ADR-032 — Password-protected hosted proof of concept

Accepted by the coordinating owner on2026-10-10 following the owner's explicit request for a temporary workaround for PostgreSQL and production identity prerequisites. This extends ADR-031; all other agents remain paused. It does not authorize deploying or relaxing the ordinary API's synthetic loopback/session/RLS guards.

Add an explicit HOSTED_DEMO_ENABLED=true launch mode. It runs only Next at the assigned PORT, requires a strong server-only DEMO_ACCESS_PASSWORD and DEMO_SESSION_SECRET plus WEB_ORIGIN, and never starts the API, worker, PostgreSQL, migrations, provider or outbound transport. The root workspace routes to an isolated /demo experience; ordinary BFF requests deny in this mode. Missing/invalid demo configuration fails closed. Ordinary launch continues to require an explicit non-owner DATABASE_URL.

The demo uses fictional fixtures and browser-memory state only, with conspicuous temporary-data labeling. It previews dashboard, contacts/pipeline/tasks, synthetic listings, website content and message drafts; saving changes affects only the current page session. Reload resets the fixtures. It provides no real customer records, persisted commands, external deliveries, feed access, publishing, production membership or authorization. It introduces no API contract or alternate handwritten SaaS client.

Access uses a shared preview password with fixed-size timing-safe comparison, bounded same-origin POSTs, rate limiting and an HMAC-signed one-hour HttpOnly/SameSite=Strict cookie scoped to /demo. Hosted HTTPS cookies are Secure. Logout requires current signed-cookie CSRF and origin verification; changing the signing secret revokes sessions. Password/signing values stay out of source, NEXT_PUBLIC variables, logs and browser bundles. Session HTML/RSC and demo routes are private/no-store; the existing service worker caches only safe static assets and a generic offline shell. No localStorage/IndexedDB draft persistence or offline mutation is added.

Use reviewed shared design tokens, semantic controls and responsive layouts. Tests prove disabled/configuration/tamper/expiry/origin/body/rate/CSRF boundaries and fixture-state behavior, followed by real local launcher and HTTP route verification. No browser/axe/physical-device or GoDaddy acceptance is claimed from these checks. The full authenticated application still requires PostgreSQL/PostGIS, production identity and all release gates; removing demo mode does not promote temporary demo data.
