# ADR-030 — Pinned compiled API and worker artifacts

Accepted bounded W01/W11 build preparation on2026-10-10 before consumer changes. The selected XWeb Pros target requires repeatable web/API/worker artifacts. This decision adds a local build/start seam, not host provisioning, production identity, worker discovery, an OCI image or release authorization.

Compile only the API and worker entrypoints and their transitive TypeScript/JSON dependencies using a dedicated configuration derived from the reviewed root CommonJS/Node compiler settings. Use Node24.19.0 and TypeScript5.9.3; the builder checks the installed compiler against the workspace pin and records it in the manifest. Nest12 dependencies are ESM; their synchronous CommonJS loading must be verified on the pinned Node runtime rather than assumed from TypeScript success. Do not compile tests, seed/migration tools, web source or unrelated fixture payloads into this artifact. TypeScript's actual emitted graph and copied JSON resources are the authority.

Build into a fresh owned workspace dist directory, then install the successful result at dist/runtime. The builder checks resolved workspace/target paths and a fixed ownership marker before any recursive cleanup/replacement. Refuse symlinks or unowned existing output. Failed compilation preserves the previous artifact. Output contains an explicit CommonJS package marker and a sorted file/hash/size manifest without timestamps, credentials, environment values or private source payloads. Identical source/runtime builds must have identical manifests. Build commands are serialized; replacement is not an atomic release swap and a filesystem replacement failure can require a rebuild. The build directory is not a live deployment release path.

Add compiled API startup using its CommonJS entry identity while preserving the existing source CLI path. Importing the emitted API module must not start a listener. Keep the loopback defaults, synthetic identity checks, current permission/RLS roles, private storage mode and all no-delivery/provider gates. Startup reports the actual identity configuration state; compilation cannot establish production authentication.

Root commands build API/worker plus the Next production build, with separate start commands for each process. Runtime dependencies remain exactly pinned in the existing lockfile. Starting an artifact needs explicitly configured application environments and private role URLs; no build/start command loads ignored secrets, runs migrations/seeds or deploys automatically. Future deployment copies the exact committed release and production dependencies into an immutable release directory and separately supervises web/API/worker.

Verify compilation/resource hashes, repeated manifest equality, import safety and compiled loopback API health plus production synthetic-session denial. Worker verification must not dispatch interactive work: use an explicit empty trusted-context configuration to prove fail-closed startup, then separately use the existing disposable recovery harness for domain behavior. No real outbound calls, server credentials or host connection are needed. Actual Linux/host execution, production identity/private adapters, supervision, backups/recovery and M8 remain open gates.

`pnpm verify:runtime` independently walks the owned artifact tree and checks the complete size/hash manifest before executing probes. Child-only TCP connection/listener guards record attempted effects, so inert API import and empty-context worker rejection require observed zero attempts. Probe environment contains no inherited database/provider/Node options; captured output is bounded and termination escalates within fixed deadlines. Corrupt/missing resources and unexpected manifest/tree records must fail before execution.

`pnpm verify:runtime:local` explicitly uses only the existing loopback fixture database and non-owner runtime role. It does not load secrets, migrate, seed/reset, mutate roles or dispatch a worker. Owned API children prove compiled health, synthetic sign-in/read/revocation, forwarding denial, production denial with both development flags, and natural process exit after app.close. A compiled CLI instance proves its actual listener via a synthetic non-secret ownership marker; its forced Windows stop is not graceful-shutdown evidence. A separate held-port CLI probe proves failed-listen cleanup. HTTP probes reject redirects. Created sessions are revoked and owned processes closed in finally. The CI steps are authored; local Windows results do not establish a successful Linux/remote run.
