# W06 native message-design storage candidate review

Proposal for ADR-026 and MOD-E-001, prepared on 2026-10-10. The exact candidate is `native-message-design-storage.sql` in this directory. It requires actual migrations 0001–0018 and the accepted static native schema and reference-only event. It has no allocated migration number and has not been executed. This note records source review and the required independent disposable-database probes; it does not claim storage or M4 acceptance.

## Reconciled schema and behavior

The original message-design aggregate lacks the frozen API's optional subject, lifecycle availability and immutable source history. Its positive integer `version` is distinct from the positive bigint `row_version`; inspection of 0001/0002 found no generic trigger that advances either. The candidate adds nullable subject, draft/archived availability and a false-by-default history marker. POST starts at ordinal/row revision 1; an approved PATCH holds the aggregate UPDATE lock, protects tenant/ID/channel/editor/creation time/lifecycle, advances both revisions once and appends a copied immutable snapshot. Integer or bigint exhaustion denies before arithmetic. No runtime lifecycle/delete command is added.

Names and provided subjects are bounded nonblank single-line text. Subject is optional for both channels. The candidate validates the already approved closed native schema, code-point limits, exact LF-joined block content, static syntax restrictions, SHA-256 and the escaped UTF-8 write-body ceiling. It accepts no Unlayer license assumption, markup, external URL or merge/template grammar. Name remains an ordinary label, not executable content. These database coupling checks supplement the authoritative generated HTTP validation and pure own-data preparation; they do not authorize sending.

`message_design_revision` records the aggregate's actual locked ordinal, SQL row revision, metadata, native design, rendered text and hash. `campaign_workflow_design_reference` records tenant/workflow/node/design/ordinal/hash with tenant-qualified source and workflow FKs. Both tables use FORCE RLS and immutable UPDATE/DELETE triggers applying to all roles. The source revision FK is immediately enforced. The workflow FK is deferred so a private BEFORE trigger can capture bindings before `INSERT ... RETURNING` applies its SELECT checks; a later statement or commit failure must roll back the aggregate and every binding/snapshot.

Existing rows retain `history_ready=false`; existing immutable workflow versions retain `design_bindings_ready=false`. No old aggregate or graph is rewritten, and no present-day content is assigned to an old reference. A valid new actual migration-owner design INSERT after adoption records a truthful observed snapshot. Explicit malformed/unlicensed new fixtures remain unavailable and receive no snapshot. Migration-owner workflow INSERTs remain unresolved when message-bearing because the historical source time is unknown. Existing wait/task/condition-only versions keep the safe no-message read branch, subject to existing draft parent, verified context and current capability/permission rules. Malformed JSON is guarded before array expansion, and the existing application still rejects invalid graph semantics and condition sources.

## Authority, policies and private helpers

The forward candidate explicitly drops 0017's ALL restrictive design policy with `WITH CHECK(false)` and replaces it with restrictive SELECT/INSERT/UPDATE/DELETE policies. UPDATE USING remains eligible for source SHARE locks. Actual mutation requires organization-scoped campaigns.write, a current active membership/role/organization and enabled unexpired marketing capability; DELETE always denies. Column grants permit only approved create/edit payloads and row-version lock support, not caller-prescribed ordinal, history marker, availability, channel/editor edits or arbitrary timestamps. SELECT permits the read or write authority needed by explicit command RETURNING; HTTP reads continue to require their frozen read permission.

Runtime receives only current revision identifiers/hash/row revision, and binding source identifiers/node/ordinal/hash. It cannot read historical bodies or private capture provenance and cannot write either immutable table. Worker, control and staff issuer receive no grants. Trigger/hidden helper execution is revoked from PUBLIC; only safe context/no-message predicates and the scoped Boolean proof have runtime EXECUTE. Every definer helper pins pg_catalog and qualifies relations. Actual runtime session identity and role setting, current tenant/actor and current grants/capability are checked rather than treating supplied IDs as authority. Missing context and masked administrator SET ROLE calls deny.

The design guard locks membership/role/organization and capability and rechecks real database time after waits. New workflow capture runs after the existing `campaign_version_native_sequence` BEFORE trigger by the explicit alphabetical name `campaign_version_zz_native_design_prepare`. PostgreSQL evaluates column defaults, including the UUID, before these row triggers. The existing allocator holds the draft parent UPDATE lock and verified authority locks. Capture checks a closed bounded graph storage shape, then locks distinct normalized source UUIDs in sorted order with SHARE; repeated nodes reuse the same authoritative source snapshot. It reloads each source after lock acquisition, requires native draft availability and history proof, verifies channel and every copied field including `source_row_version`, then rechecks capability/authority before and after binding insertion. The application remains responsible for full DAG semantics and current CRM condition-reference authorization through its existing ports.

A PATCH's UPDATE lock and capture's SHARE lock serialize the routine reference/edit race. Any preserved typed binding, workflow JSON reference, campaign-step reference or scheduled-action reference freezes the entire design, including metadata. The hidden check scans the verified current tenant across unreadable published/legacy definitions and tolerates malformed nested JSON without returning its contents. Future step/scheduler write ports must adopt the same source locking rule before any grants are added. Privileged fixture/migration maintenance is not a concurrent runtime reference API.

An actual migration owner may only archive an aggregate while retaining its content/ordinal; row revision advances and ordinary reads/use fail. This private maintenance transition is not a new runtime endpoint. No archive unavailability is hidden by falling back to the stored history.

## RETURNING proof and visibility

PostgreSQL 17 applies SELECT policies to INSERT RETURNING as insertion checks. Capturing only in an AFTER trigger or requiring the new workflow tuple to exist during that check would incorrectly reject an otherwise valid creation. This ordering is confirmed in the [PostgreSQL 17 row-security rewrite source](https://github.com/postgres/postgres/blob/REL_17_STABLE/src/backend/rewrite/rowsecurity.c); the candidate still requires an actual-role regression for the precise new-row cut point.

The callable Boolean proof first verifies actual runtime/current tenant/current actor/current organization authority and DB-clock capability. A current-tenant existing version must be a draft with no publication time, an exact stored definition and a current draft parent. Hidden published/history IDs return false even if a caller knows the full graph. No lookup crosses the already verified tenant.

Only a missing workflow row may use private BEFORE-capture provenance: captured parent UUID, initiating actor UUID, xid8 transaction identity and the SHA-256 of the exact JSONB definition. The trigger derives those values from NEW and the verified transaction; runtime cannot insert, change or select them. All node bindings must match the current actor/transaction/exact graph and a current draft parent. This is a narrow exception for the pending insertion, not a forgeable session GUC, context token or hidden history directory. Once the row exists, the ordinary existing-row draft guard applies; deferred FK enforcement requires the same version row before COMMIT. PostgreSQL supplies [xid8 transaction identity](https://www.postgresql.org/docs/17/functions-info.html#FUNCTIONS-PG-SNAPSHOT) and [core SHA-256/UTF-8 byte functions](https://www.postgresql.org/docs/17/functions-binarystring.html) without a new dependency or cryptographic extension.

ADR-026's shared design must explicitly include this private capture provenance and deferred-FK exception before consumer adoption. Source proof compares current ordinal/hash, SQL row revision and all aggregate metadata/content against the immutable revision. Matching a body hash alone never proves a source revision.

## Independent acceptance matrix

The coordinator/test owner should commit the exact candidate, execute it after 0001–0018 in a uniquely owned disposable database under the separate migration identity, and verify at least these actual-login groups. Preserve global role attributes/memberships and remove only owned fixtures/database.

1. Forward application/checksum rerun, new FORCE-RLS tables, exact minimal column privileges, fixed helper search paths and PUBLIC EXECUTE revocations. Existing rows/immutable versions remain unchanged and unproven.
2. Actual runtime native INSERT RETURNING: optional subject, exact known hash, one copied revision and initial ordinal/revision. Repeat email/SMS, Unicode/code-point bounds, LF/tab content, single-line subject and escaped UTF-8 boundary cases. Malformed format/content/hash/editor/extra properties deny atomically.
3. Unreferenced PATCH RETURNING advances both revisions once with exactly one new copied snapshot. Protect IDs/tenant/channel/editor/ordinal/lifecycle/markers/timestamps; reject missing history or mismatched row revision/metadata. Verify read-only SHARE succeeds but no-op/write attempts without write authority deny.
4. No-context, pooled reuse, foreign tenant/actor, inactive member/org, missing/expired capability, own/team-only campaigns scope, worker/control/issuer and masked administrator calls deny. Show known foreign/published IDs and malformed helper arguments return false without errors or metadata.
5. Private revision/binding INSERT/UPDATE/DELETE and history-body/provenance SELECT deny. Even migration-owner UPDATE/DELETE cannot alter immutable rows. New valid migration-owner inserts create observed history; old rows receive none.
6. New runtime workflow INSERT RETURNING with one and repeated email/SMS sources creates exact node bindings using the current actual source ordinal/hash. Source SHARE remains held. Existing no-message workflows remain readable; legacy message versions and malformed definitions remain unavailable without mutation/backfill.
7. Wrong channel, archived/unlicensed/unproven/missing source, mismatched snapshot name/subject/body/hash/version/row revision and invalid closed graph fields deny. Source references are current at read/replay as well as creation.
8. Scoped proof for known hidden published ID, stale/non-draft parent, changed supplied graph, forged actor/transaction/parent, missing row without private capture and another tenant denies. Verify provenance column privileges separately. Confirm a later transaction cannot reuse absent-row proof.
9. Observe the actual BEFORE/RETURNING boundary; force later INSERT/check/FK/statement failure and caller rollback, confirming zero orphan bindings/history/aggregate/event/receipt. Force deferred FK failure at COMMIT and verify rollback. A valid new RETURNING result commits only with its own workflow row.
10. Existing hidden published/legacy nested JSON, typed workflow, campaign-step and scheduled-action references deny every PATCH, including label-only edits and no-op updates. No hidden reference identifiers appear in the safe failure.
11. Genuine two-client reference SHARE versus PATCH UPDATE races in both orders: capture waits and binds the updated valid revision, or PATCH waits then denies once a reference commits. Check deterministic multiple-source lock ordering and one source snapshot for repeated nodes.
12. Capability/grant/member/parent/source revocation after real lock waits denies using clock_timestamp, with no partial revision/binding writes. Archive maintenance preserves history while current read/use rejects; no live worker or provider invocation occurs.
13. Positive integer and bigint design exhaustion, hidden published workflow sequence allocation and unrelated previous wait/task/condition acceptance remain intact.

Service/HTTP command acceptance remains dependent work after this candidate passes and is promoted: frozen MessageDesign shapes/status/ETag, strong If-Match/CAS, same-key concurrency and historical receipt conflicts, atomically committed design/snapshot/audit/reference event/receipt, complete private bounded list pages and explicit copy UI. No SQL trigger fabricates an outbox event or success receipt. This proposal enables no publish/enrollment/schedule/delivery/provider authority and no interactive fixture renewal.
