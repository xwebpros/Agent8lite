# W06 native static message-design draft prerequisite

Proposal only for the next bounded MOD-E-001 slice. The source is MOD-E and frozen MessageDesignWrite/MessageDesign/PageMessageDesign plus ADR-023's accepted `native-message-text-design-v1.schema.json`. The only implemented files are the pure preparation module and its tests. No message-design service, route, write privilege, migration, editor adapter or delivery path is added.

## Pure preparation contract

Direct server import `packages/marketing/native-design.ts` exposes generated `NativeMessageDesignWrite`/`NativeMessageDesign` aliases, `prepareNativeMessageDesign(input)` and `NativeMessageDesignError`. Preparation returns a detached deeply frozen write body, canonical body/design JSON, exact rendered text and lowercase SHA-256 of its UTF-8 bytes. These are internal preparation fields, not a second HTTP contract. The package browser entry does not export this server-only crypto/util/Ajv module; exports require coordinator review.

Both the frozen write schema and approved closed static native schema are validated. Optional subject is preserved; an email subject is not fabricated or made required. Any provided subject must be nonblank single-line static text without ASCII control characters, including LF, CR and tab. Allowed LF/tab text in content/blocks remains unchanged. Names are nonblank, at most 120 Unicode code points and contain no control characters. Blocks are 1–100 closed text blocks; each is nonblank and the supplied content must exactly equal their text joined by one newline. Frozen subject/content bounds count code points. The complete escaped UTF-8 write body is limited to 256 KiB, independently of those field bounds. Input text is preserved without trimming or Unicode normalization.

Preparation reads only own enumerable JSON data descriptors. Accessors, proxies, custom prototypes, symbols, hidden properties, sparse/extraneous array properties, cycles, non-JSON values and depth over 20 deny without invoking hooks. Canonical serialization sorts object keys and never calls object/array `JSON.stringify` or inherited `toJSON`. Consumers must use its prepared canonical strings for hashing/persistence rather than reserializing caller input after waits.

The current ADR-023 workflow source predicate is matched for content, blocks and subject: markup delimiters, merge/template openings, forbidden control characters, javascript/data/http/https/ftp scheme syntax and `www.` deny. Unlayer denies with `native_editor_unavailable`; no license or readiness is inferred. This is static plain text, with no HTML sanitization/rendering, arbitrary template engine, external URL resolution, sender verification, SMS billing/segment estimate or permission to send. A later approved editor/merge/link catalog must explicitly replace this restrictive prerequisite.

## Contract and storage discrepancies

Frozen GET/POST/PATCH message-design routes use `campaigns.read/write`; PATCH requires Idempotency-Key, CSRF and If-Match and returns the same aggregate ID with an incremented `MessageDesign.version`. The table currently lacks the contract's optional subject. Current 0017 grants only SELECT and UPDATE(row_version) for FOR SHARE, with restrictive WITH CHECK(false); it deliberately denies actual writes. Adding another permissive policy or grants alone cannot authorize writes, and weakening that policy without reviewing source-lock semantics is unsafe.

Workflow nodes store only messageDesignId. Updating design content in place would silently change the meaning of an already saved immutable workflow, and neither the workflow response nor its JSON supplies a historical design ordinal. PATCH must not return a new aggregate ID to disguise this mismatch. Existing historical content cannot be recovered from a current row or guessed from timestamps.

## Recommended initial history rule

For the first write slice, retain a stable message-design aggregate ID and append an immutable snapshot for every create/update, with design JSON, rendered text and hash versioned together. PATCH is permitted only while that design has never been referenced by an immutable workflow or other preserved execution object. Once referenced, the design's complete metadata/content/channel/editor/subject become immutable; PATCH returns a safe `409 design_referenced_immutable`. Authoring a changed design then requires explicit POST with a new ID and a new workflow draft. This conservative rule preserves the existing UUID-only workflow semantics and makes historical reads truthful without adding an undocumented revision-read route.

A typed immutable workflow-to-design binding records the exact source ordinal/hash at workflow creation. It enforces referential history and future-use inspection independently of mutable JSON scans. Bindings and design changes use the same design row lock: workflow creation holds SHARE while inserting bindings; PATCH holds UPDATE and denies after rechecking bindings. Thus concurrent capture of a reference and update cannot both succeed against incompatible source states. Current capability, tenant, parent lifecycle and source-read authority remain required; a preserved snapshot never grants sending or overrides archive/revocation.

A later revision-bound editing model may allow PATCH after reference by resolving each workflow through its bound immutable source revision. It needs an approved historical-reference read/UI contract and revised source port before use. This proposal does not implement that broader behavior. Published workflow/history must not silently switch to a newer design.

## Forward migration prerequisites before consumers

The coordinator allocates and adopts the actual migration after independent disposable real-role probes. Proposed additive storage:

- Nullable bounded `message_design.subject`, with existing rows backfilled to NULL. Internal draft/archived availability may be added, defaulting explicitly to draft for approved existing records; no runtime archive/delete command is implied. Public generated response shape stays unchanged.
- `message_design_revision`: tenant ID, design ID, positive bounded ordinal, server timestamp, name, channel, subject, editor, closed design JSON, rendered text and hash; composite primary key and tenant/design foreign key. Append-only trigger and FORCE RLS. A narrow insert trigger copies the locked aggregate's actual fields instead of trusting arbitrary caller snapshot content. Runtime gains only the reviewed INSERT identifiers; no UPDATE/DELETE and no broad historical directory reads.
- `campaign_workflow_design_reference`: tenant ID, workflow-version ID, node key, design ID, source ordinal and source hash, with immutable composite keys and foreign keys to the immutable workflow and source revision. Its insert checks the current draft graph/node/channel and current source revision under the same transaction/locks. Runtime reads only references belonging to currently readable drafts, not hidden published definitions.
- Preserve lock-capable SELECT/UPDATE USING on current eligible native sources. Replace 0017's single ALL restrictive policy only in a reviewed forward migration with command-specific restrictive policies: SELECT preserves current-source isolation; INSERT requires verified context/native draft/initial versions; UPDATE permits only reviewed native unreferenced drafts, with source identity/lifecycle/channel/editor protected. A narrowly audited trigger may check hidden historical reference existence across all states, with fixed search path, safe errors and no public callable metadata-returning function. Runtime receives only required column privileges, never broad UPDATE/DELETE. Worker/control/issuer grants remain unchanged.
- Serialize public design ordinal and optimistic update under the aggregate lock, use quoted positive `MessageDesign.version` If-Match and a conditional row-version CAS, deny integer exhaustion, and recheck DB-clock marketing capability/organization-scoped campaign authority after waits. Append snapshot, safe audit, durable canonical-body receipt and a reviewed closed internal design-draft-changed reference event atomically; event payload contains only safe IDs/ordinal/operation, never design, subject or body.

Backfill existing workflow references only from authoritative source history. Missing historical proof must be marked unresolved and fail closed; do not assign today's content to an old workflow or rewrite an immutable definition. Existing workflow fixtures with no authoritative revision require an explicit reviewed synthetic repair decision. Native records using another format or unknown licensing remain unavailable. No consumer assumes these tables/policies/events exist before shared commit.

## Acceptance proposal and current evidence

Pure preparation passes 49/49 targeted tests: exact known SHA-256, block joining/Unicode preservation, single-line subject versus multiline content rules, code-point and escaped UTF-8 bounds, input immutability, key-order canonicalization, frozen/internal closed schemas, unavailable syntax/editor and safe errors, proxies/accessors/cycles/sparse arrays and inherited Object/Array toJSON counter zero. Whole-repository TypeScript and the two owned-file Biome checks pass. This establishes no SQL or route acceptance.

After shared approval, real-role tests must prove minimal grant/RLS/missing-context/pool reuse, native-only coupled revision snapshots, immutable history, optional subject persistence, scoped current reads, same-key concurrent create/update and historical receipt conflicts, strong revision races, expiry after advisory/design locks, full caller rollback and closed event deferral. Test a genuine SHARE reference versus UPDATE race, published/hidden reference denial, deletion/archive/current-rights denial without historical fallback, and unresolved legacy references. Required HTTP/private/mobile UI and broader Unlayer/render/publish/send/recovery acceptance remain future gates.
