# W07 current synthetic session read boundary

The reviewed handler accepts the existing verified `ServerSession` from the shared router. Shared `readSession` checks that row in a separate transaction, so its returned value can become stale before MLS reads acquire their later source locks. INV-01 requires current identity as well as current membership, capability and source rights.

Keep the existing entry point and frozen responses. Inside the owned `withTenantTransaction` callback, use the trusted server-held token hash to set transaction-local `app.session_hash`, then SHARE-lock the matching `app.login_session` row bound to the verified user and active organization. The existing 0002 session RLS policies and runtime SELECT/UPDATE privileges already permit this lock; no shared grant/schema change or session issuance/update/delete is proposed. Raw session tokens, CSRF material and session metadata are never exposed in listing DTOs, errors, logs or cursors.

Check expiry with a separate `clock_timestamp()` query after acquiring the session lock. A time predicate in the locking SELECT can be evaluated before a lock wait, so it cannot alone prove current validity. Repeat current expiry validation after the listing operation returns and before caller commit. Hold the session lock through that commit; concurrent revocation or active-organization switching must serialize with the read. Missing/revoked/mismatched/expired sessions produce the existing safe 401 `session_expired` error.

The shared router continues to own cookie/session resolution, synthetic mode, rate limiting and private/no-store responses. The service-level port still requires a verified tenant transaction supplied by its caller; only the HTTP handler adds the server-session check. No public route, authentication mode, session lifetime, provider connection or outbound action is enabled. Root reviews this owned hardening at import; shared auth implementation remains untouched.

Acceptance is real nonowner runtime-role HTTP against a disposable database: retained session denial after revoke/switch; list and detail expiry while blocked on source locks; expiry while blocked on the session row itself without a writer tuple update; revocation waiting for an in-flight read to commit; transaction-local session context cleared on pooled reuse. Browser acceptance is separate and pending.
