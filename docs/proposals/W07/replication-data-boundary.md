# W07 pure replication data boundary

The user's continued coding request covers a bounded correction to the existing owned pure checkpoint helper. This changes no shared provider/ordered-source interface, public request/response, SQL, grants, routes, worker registration or approved licensing decision. The guarded storage candidate remains unexecuted. ADR-025's fixed ordered source remains separate; its approved own-property repair is imported unchanged from coordinator `4f2a100` as `87118b1`.

The existing helper validates checkpoints and current feed bindings by ordinary property reads. `structuredClone` also evaluates enumerable getters on caller/provider objects. Consequently a valid-looking getter can run during checkpoint creation, authorization, source page cloning or commit acknowledgment. The second authorization check and capability/error classification also read returned values directly. A malformed object can throw before a safe checkpoint result, execute a callback hidden in data or produce a valid plan from executable properties. Caller and returned values are data boundaries; explicitly supplied service/provider objects, metadata and methods are trusted implementation code.

Before any value access, detach a bounded own-data JSON tree using descriptors. Reject proxies before reflection, accessors, functions/toJSON hooks, symbols, hidden properties, custom prototypes, cycles/depth overflow, non-finite/negative-zero numbers and sparse/augmented arrays. Permit ordinary/null-prototype records and dense arrays. Use the fixed ordered source's conservative bounds: depth 12, 40,000 nodes, aggregate string bytes 3,000,000, 25,000 code units per string, 64 keys per object and 500 entries per array. Never log rejected objects or arbitrary exception text.

Apply this privately to checkpoint creation/validation, current feed binding, both authorization snapshots, capability/page data and returned commit receipts. Valid data retains current sorted-key hashes, immutable plans, limits, fixture-field normalization, policy rechecks and checkpoint semantics. Read faults use own data descriptors for the existing typed code/retry fields; proxies/accessors cannot become recognized faults. Trusted ports themselves and their methods are not JSON-cloned. Awaiting them uses JavaScript's native Promise protocol: thenable resolution can run before the helper receives the value. The boundary rejects data/reflection hooks after that point; it cannot sandbox trusted callbacks or their Promise resolution. Returned-proxy tests allow the native `then` lookup and require zero subsequent data/reflection traps.

Unsafe checkpoint input returns `invalid_checkpoint` before ports run; creation throws that fixed message; binding returns null. Unsafe authorization returns `policy_denied`; unsafe capability/page data returns the existing `read_failed`. Unsafe acknowledgment requires `commit_unknown` reload because durable effects may already exist. No new error code, automatic retry or persistence authority is introduced.

Commit this prerequisite before implementation. Reproduce boundary failures with own getter/proxy counters and real mock fixtures, then verify zero hook/trap reads, no read/commit on rejected precommit data, exact authoritative state after malformed postcommit acknowledgment, accepted null-prototype JSON and caller mutation isolation. Run focused then retained pure/provider suites, scoped/root TypeScript, formatting and frozen contracts. This proves pure data-boundary behavior; no database/browser/live provider evidence follows.

## Executed correction evidence

Prerequisite `651c274` preceded consumers. The new 38-case suite reproduced **35 failures/3 passes** on the original helper, including executable getters and rejected proxy promises. The final focused boundary plus retained replication suite passes **130/130**, and the full owned pure/static/provider suite passes **509/509 across 14 files**, without skips. Scoped/root TypeScript, 48-file owned Biome, frozen contracts (170 operations/169 schemas plus ADR-022), diff and property browser source graph all pass; that graph creates only two in-memory outputs and contains no Node/server modules.

One intermediate failure exposed a test fixture's native Promise `then` lookup before data reached the helper. The returned-proxy fixture now permits that protocol lookup while counting and rejecting all subsequent data/reflection traps; no product guard was relaxed. Ordinary/null-prototype JSON produces identical checkpoint results/receipts, and source mutation during the second authorization wait cannot alter the detached plan. Malformed postcommit acknowledgments leave exactly one committed test-ledger effect and return reload-required, with zero data getter reads.

Only the existing pure helper and a private snapshot utility are changed. No shared interface/export/dependency, provider implementation, SQL candidate, database, role, router, browser, source configuration or worker registration changes. The resource bounds are deliberately conservative: they can reject otherwise schema-valid unusually large pages, requiring reviewed initial page sizing before future ingestion. No automatic smaller-page retry or cursor reset is added. These are pure mock/test-ledger results, not durable PostgreSQL ingestion or browser/device acceptance; coordinator integration and existing storage prerequisites remain open.
