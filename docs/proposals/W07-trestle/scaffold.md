# Trestle provider scaffold

Requirements: MOD-F-001, 002, 003, 006, 007 and 008. This additive internal proposal does not change frozen public contracts, database grants, routers, existing mock services or provider activation.

Implement a server-only OAuth client and `LiveQueryAdapter` behind the existing MLS port. A trusted feed authorization resolver must bind organization, feed and policy version, current connection approval, broker contingency, explicitly licensed originating-system IDs, observed source fields and the current display policy. Recheck authorization after every network operation; deny unknown or revoked rights before obtaining credentials. Product/feed credentials come from a scoped server secret source, never a request or public DTO.

The access probe is a separate explicitly enabled server command: one authentication request and one XML metadata request. It prints safe diagnostics only. It does not download properties, publish listings, write the database, accept contracts or create paid connections. Application selection stays `MLS_PROVIDER=mock`.

The initial adapter supports bounded OData search and detail with selected fields, mandatory source-system filtering, safe literal compilation, current field/status/address rights, no-store requests and an opaque process-local continuation. Unknown fields/statuses, synthetic records, arbitrary endpoints, redirects and cross-origin continuations deny. Keyword functions, durable replication/checkpoints/deletion reconciliation, media, maps without exact-location rights, alerts and AI are not claimed enabled. The native mock repository must not be used to store live records; integrating a live repository/scheduler requires coordinator review and the M6 mapping/rights acceptance gate.

Sources reviewed: owner-supplied Technology Providers Release v3 guide, PDF pages 6–10 and 25–31; Multiple Listing Managers Release v3 guide, pages 2–4, 8–10 and 13–15. The public documentation at https://trestle-documentation.corelogic.com/web-api/ and /web-api/reference/ was checked on 10 October 2026. The older guide uses CoreLogic endpoints and a 3600-second token example; the public page uses api.cotality.com and a different lifetime. Confirm the actual account endpoints and honor `expires_in`; do not infer feed rights from either example. Source PDFs and credentials are not copied into the repository.

Before the joint access test, the owner confirms the registered product, feed type, MLS and connection approval, broker authorization if required, intended use and credential expiry. The owner stores the client ID and secret directly in an ignored local environment file or a server secret manager. No credential is pasted into chat. Metadata access is the first test; listing reads follow only after field/display/retention/media policies are mapped and accepted.
