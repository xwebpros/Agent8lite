## Frozen HTTP contract and job semantics

Keep the following operations and bodies unchanged:

| Operation | Authorization/input | Frozen successful response |
| --- | --- | --- |
| `POST /v1/orgs/{orgId}/documents/{documentId}/publish` (`publishDocument`) | Organization `content.publish`; selected member organization; CSRF/origin/rate guards; Idempotency-Key; closed `PublishRequest` | `202 Job` |
| `POST /v1/orgs/{orgId}/documents/{documentId}/rollback` (`rollbackDocument`) | Same guards; explicit historical revision | `202 Job` |
| `GET /v1/orgs/{orgId}/jobs/{jobId}` (`getJob`) | `jobs.read`, current membership and existing requester restriction | **202 Job**, including terminal states, in the present frozen specification |

`PublishRequest` contains exactly `revisionId: UUID` and `expectedDocumentVersion: integer >= 1`. It has no If-Match header requirement, site ID, host, publication mode, media/form bypass flag or release ID. Use its version as the mandatory compare-and-swap precondition, additionally rejecting values outside the database/JavaScript safe version range. Do not make a new mandatory header or substitute the selected revision UUID for a version. If root wants `getJob` to return 200, review/change the shared contract first; do not silently diverge.

`Job` permits only `id`, `state`, `kind`, `createdAt`, optional `resultUrl`/`error`; its states are queued/running/succeeded/failed/cancelled/unknown. Recommend closed internal kinds `cms.publish.v1` and `cms.rollback.v1`. Return null resultUrl initially. The current job model maps unfamiliar safe_error values to generic 503; the job owner must review closed CMS error projections such as revision_changed / 412, publication_invalid / 422 and publication_revoked / 403 before promising specific failure reasons. Poll itself remains 202. Errors contain no draft JSON, SQL or private profile/provider values. Queued/running means accepted/executing. Succeeded means the public database transition committed, not that an enqueue or reference-ledger receipt happened. Unknown is for unresolved external acceptance; the initial internal PostgreSQL path can determine completion from its durable release/job rows.

Preserve requester-only polling even though the permission catalog supports organization-scoped `jobs.read`; widening that existing row scope needs separate review. Require that scope explicitly. A CMS job polling adapter must additionally check current websites capability and eligible CMS sources; `requireEntitlement(client, 'jobs.read')` currently performs no feature check. Poll safe job metadata through the shared job owner, without returning the internal command/snapshot. Website-health UI later needs actual active-publication/binding state, source and refresh time; it cannot infer current visibility from an old succeeded job.

## Recommended first safe slice

Implement one document publication on a platform-controlled, exactly registered production host, using only schema-v1 hero/text/CTA/footer, plain text, approved HTTPS/local links and pinned platform styling. Only explicitly published route entries are visible; first publication of one document does not expose the site's other drafts. Local links may lead to a generic 404; a `/contact` link does not create a form or claim CRM capture.

The minimum wait/task analogue is one durable queued job, PostgreSQL polling/recovery, a fenced claim and one atomic internal publication task. Enqueue is the wait state, not completion; no deployment provider or generalized workflow runner is required for this slice.

Reject the entire command on unknown/older schemas, unknown blocks/properties, nesting, duplicate IDs, invalid JSON/limits, unsafe links, assets/social-image references, forms, listing/search/map/agent data references, arbitrary HTML/CSS/scripts or remote fetching. Preserve their native revisions for recovery. Existing media rights/scan fields, form definitions and MLS metadata/credentials do not confer display rights. These references have no permissive resolver in this slice. Text entered by the author is rendered as text; no private profile fields or provider data are automatically hydrated into it.

Validate the exact repository theme version and renderer/policy version, with no fallback. A publication freezes title, kind, slug/route, theme, SEO and immutable revision/hash together. Editing private document metadata or adding a draft afterward cannot change that public snapshot. Canonical URL uses the verified production origin plus the frozen route; recommend that an explicit canonicalPath match that route initially. Respect noindex; omit social-image output. Reject reserved staff/API/preview paths. Render a complete escaped server HTML page with static platform assets, restrictive CSP, nosniff and no tenant script/inline-handler execution; current fragment rendering alone is insufficient.

No preview URL becomes a production route. Signed preview requires a separate reviewed token/host contract, expiry/current access checks and private no-store handling. It is absent from the frozen operations inspected here and remains a prerequisite before claiming the full draft→preview→publish M3 workflow. Synthetic acceptance may use explicitly registered fixture hosts and fake verification/TLS evidence in its disposable harness, never production DNS/certificates or a Browser Block bypass.

## Proposed service ports and trust boundaries

The names below are proposals, not new runtime or handwritten HTTP contracts. Root adopts exact shared declarations/schemas before consumers. Frozen command/result aliases come from generated `components['schemas']`.

| Port/owner | Concrete responsibility |
| --- | --- |
| CMS publication command port | `publish(documentId, PublishRequest, key)` and `rollback(...)` return `{status:202, body:Job}` in the existing verified caller transaction. Resolve site/revision from the path document, never client site/tenant claims. Keep member/role/organization/source locks and current `content.publish`/websites checks after waits and before return. |
| Administration publication-reference port | Same transaction/verified context; return only matching profile/organization identity after current publication eligibility checks. Explicitly support a publish-only grant. Root must define public profile eligibility using the real schema; no invented archive JSON flag and no public private-profile projection. |
| Foundation publication-job port | Atomically create the requester-bound integration job, transition only registered CMS jobs, and project the frozen Job. CMS does not directly mutate unrelated administration/billing job rows. Durable job creation and CMS command FK use the same PoolClient, not nested transactions. |
| Hosting/public-target port | Bind site to one exact normalized production hostname, current verification/TLS state, hosting environment and binding generation. Recheck before visibility. No arbitrary Host/X-Forwarded-Host, profile.websiteUrl, organization ID or preview token chooses a site. |
| Trusted rendering-policy port | Supply a version/digest for the deployed block/theme renderer and approved link-origin set, bound to the public environment/site. The current PublishPolicy carries only an origin Set, so this versioned declaration and a server-controlled current-policy marker need shared review. No visitor/tenant parameter selects an old policy. |
| CMS public-read port | Accept normalized request authority and path only; internally resolve the approved routing directory, current visibility and immutable active page. Return a bounded public projection: generated HTML/text SEO, canonical origin/path and opaque publication generation/renderer version, or generic unavailable. Never return a TenantContext, raw revision/recovery/history or private business profile. |
| Cache invalidation consumer | Consume durable publication generation/reference events, with receipts and replay-safe deletion; no raw HTML/content in events or Redis. It cannot declare CMS execution complete on the current synthetic reference-ledger receipt. |

Anonymous rendering must not borrow a staff cookie, fabricate an actor/member, use a tenant ID from the URL or run the migration owner/BYPASSRLS. Recommend a dedicated public execution role with **EXECUTE only** on a narrowly reviewed host/path resolver, and a non-login, non-table-owner, NOBYPASSRLS function owner with column-limited reads. A fixed search_path, parameterized authority/path, exact server-owned host directory, transaction-local derived public context and explicit public RLS policies constrain the function. It returns published projection only and rechecks organization/site/capability/profile/binding/archive state with `clock_timestamp()` before return. The public role gets no direct native revision/CRM/profile table reads or writes. Root/security/database owners must approve this distinct verified-public-context boundary before anonymous requests are enabled; `withTenantTransaction` currently requires active membership and is not an anonymous adapter.

## Durable acceptance, execution and rollback

1. **Accept in one caller transaction.** Verify current member organization, organization-scoped content.publish and websites capability. Lock eligible profile/site/document in the established order; bind the exact immutable matching-document revision. Validate request shape and acquire an operation/document/member-bound idempotency lock; after every wait recheck current authority and clock. Exact historical acceptance replay returns the original 202 Job after current source authorization, before testing the old expected version; a changed body/key binding returns 409. That original queued response is a historical receipt, so polling supplies current completion state. For a new command only, require current document version equal to expectedDocumentVersion and validate body/hash/theme/target; rollback also requires evidence of earlier successful publication of this revision for this document. Atomically persist an immutable command binding, queued job, safe audit and original response receipt. Acceptance changes no public route/pointer/version. Do not reuse the existing draft-only idempotency helper's permission union or mandatory response ETag without a reviewed job-specific adapter; no ETag is required on accepted Job responses.
2. **Recover and claim.** A PostgreSQL poller for explicitly configured trusted contexts discovers committed CMS jobs even if every Redis hint is lost. Resolve the stored initiating actor/member against current membership/role/organization; never deserialize stored permission grants or reuse a browser session. Job ID and tenant references identify work, not authority. Claim under a bounded lease with an incrementing attempt/fencing token; only its current holder can finalize. Current worker code does not supply this consumer. Membership/grant/source revocation cancels or fails safely with no public effect. Decide logout behavior explicitly: recommend durable work rechecking the initiating member, not depending on the continued lifetime of the original browser cookie.
3. **Validate and commit visibility in one short transaction.** Recheck job ownership/fence, current initiating member permission/capability, exact source/profile/production binding/generation, revision hash and renderer policy, then expected document version again. Avoid network/DNS/CDN calls while locks are held. Create an immutable publication release; compare-and-swap document version V→V+1 and its matching revision pointer; install the frozen route; increment a separate site publication generation and set published state/time; insert the durable invalidation event, audit and succeeded job transition together. A concurrent draft or metadata edit makes execution fail with a 412 reason via a safe job outcome, leaving the previous public page intact. Two accepted jobs at V cannot both publish. Any audit/event/job/route failure rolls the entire visibility transaction back. An invalid new job must not set a previously published site to an unavailable publishing state.
4. **Rollback is a new explicit publication.** Use the same queue, validation, current rights, fence and CAS path; never edit/delete history or decrement versions. Recommend content-revision rollback: selected previously published blocks/SEO are combined with the current, explicitly reviewed document title/route/theme at expectedDocumentVersion; private metadata is not rewritten. Canonical compatibility must pass. The request contains no historical release ID, so exact restoration of an old title/slug/theme when the same revision had several public snapshots is ambiguous. Root must approve this limited semantics or review a separate release-selection contract before promising full-page snapshot rollback. Previous rights/compatibility never substitute for current checks.

## Visibility and cache invalidation

Start with server-rendered customer pages `Cache-Control: no-store`, no ISR/CDN/browser/SW HTML persistence, no stale-on-error fallback and no unauthenticated draft/preview endpoint. A successful visibility commit writes the pointer/route/release and invalidation event atomically; the initial page needs no external cache acknowledgment to become visible. Public read always gates the **current** organization, websites expiry, site published/non-suspended state, document non-archive, eligible profile, exact production host/TLS and active release/policy before emitting HTML. Staff-author revocation blocks unexecuted jobs; it does not alone unpublish an already authorized public release. Public source/hosting/capability revocation does deny subsequent reads. This distinction needs explicit approval.

Later cache activation requires a reviewed visibility-generation design: keys include canonical binding/environment/site/document/release and renderer/policy generation, never merely slug or a client tenant. Current eligibility is checked before every hit, including conditional 304; inability to verify denies. Publish/rollback/site suspension/domain detach/archive/capability-policy changes invalidate page, route, navigation, sitemap/robots and future asset-derived entries. The invalidation consumer processes committed generations idempotently, and an old delayed event cannot restore an old route. DNS/CDN/provider acceptance that cannot be determined is reconciled rather than blindly resent. Do not claim the existing worker or in-memory browser bundle proves these guarantees.
