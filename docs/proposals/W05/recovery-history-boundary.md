## Original proposal

Proposed synthetic read: `GET /dev/orgs/{orgId}/cms/documents/{documentId}/revision-history`. Require the same explicit synthetic mode, actual loopback, selected member organization, current organization content.read, websites capability, administration profile eligibility and source locks/rechecks as ADR-020. Unknown grants/rights or foreign/ineligible documents deny before returning metadata. Root owns shared schema adoption and router/BFF registration.

The closed envelope is `{items, hasMore, nextCursor}`. Every item contains only native `id`, exact `documentId`, integer `schemaVersion` and `createdAt`. Return all eligible native revision rows in deterministic ID order, including unsupported blocks/properties/schema versions; do not widen frozen PageRevision, drop unknown rows, embed raw JSON/diagnostics or infer the latest revision. A schemaVersion of 1 is not evidence of current block/property/link compatibility. The UI labels format/version as metadata and lets a human select an explicit ID for the always-read-only recovery reader. Making supported content editable continues to require an explicit normal frozen read and strict inspection.

Use existing signed cursor mechanics with resource/document, organization/member and filter binding, expiry and the existing maximum cursor length. Proposed query keys are only limit/cursor, with default 50 and integer limit 1–100. Reject repeated/unknown keys, mismatched/expired/tampered cursors and unknown paths. Fetch one extra row to establish hasMore; nextCursor is non-null only when another page exists. Do not run frozen Revision serialization or inspect original block_data/seo to paginate metadata. Immutable-row insertion between pages follows existing stable-ID pagination semantics; this is an index, not a snapshot or chronological timeline guarantee.

Private/no-store, nosniff and trace headers apply, with no ETag or write side effect. Limit each response to 100 items and 64 KiB serialized UTF-8. Keep authorized metadata only in memory; clear it and any original recovery projection on context/access loss, expiry or offline transition. No service-worker/private browser cache, audit payload or log receives original data. Item/path document IDs must agree before a consumer opens recovery.

The companion `recovery-history.proposed.schema.json` is a review artifact only. Acceptance before consumers should prove complete mixed supported/unsupported pagination, no raw fields, exact tenant/document/member/cursor binding, native non-bypass RLS, current source/profile/grant/capability denial, clock-after-lock expiry, no publication/version/audit changes, query/response bounds and explicit-ID selection without a latest-draft inference. Real keyboard, browser/accessibility/reflow and device acceptance remain gated by the saved browser Block.
