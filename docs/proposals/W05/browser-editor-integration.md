# Bounded browser field editor

W05 now supplies `apps/web/features/cms/draft-editor.tsx`, `draft-controller.ts` and a scoped CSS module. `packages/cms/browser.ts` is the explicit browser entry point. It imports generated contract types, the unchanged frozen JSON schemas and registered block property schemas; it never imports the server CMS index, hashing helpers or renderer. Browser inspection uses TextEncoder for the same UTF-8/JSON bounds and preserves the server registry's schema, link, nested-content and media-denial rules. Parity tests keep this owned adapter aligned until a shared browser registry extraction is reviewed. Server validation and authorization remain mandatory.

Root mounts the editor under its existing client workspace. Do not pass the client/controller through a Server Component's serializable-props boundary. Create one controller per verified session/member/organization/site/document binding from an authorized frozen Document plus its strong document ETag. Inject a `CmsDraftClient`: `saveDraft(command)` returns frozen Revision plus the original response ETag; `readDocument()` returns frozen Document plus its matching ETag. Root supplies the closure's current session/CSRF, existing same-origin no-store API/BFF binding, actual approved `/dev/.../drafts` route, error `status`, permission/capability visibility and connectivity. Constructor `canWrite` reflects the current verified content-write visibility; false permits reading explicit revisions but gates blank drafts, edits and saves. Server authorization remains independent. Use a fresh browser `crypto.randomUUID()` command key. No organization/session/profile claim is accepted from the field component.

Supply authorized frozen PageRevision history, loading/failure state and a cursor callback. Merge further pages by revision ID and keep the selected ID independent of document metadata version. No UUID ordering, first item, published pointer or timestamp chooses a draft automatically. Creating a document creates no content; the explicit Start a blank draft button initializes only local memory. Exact repository template starters may be injected through a later reviewed template selection workflow; this checkpoint does not copy template definitions into the UI or instantiate one implicitly.

The plain fields cover registered hero/text/CTA/footer and SEO. Buttons add/remove blocks, paragraphs, hero actions and footer links. Move up/down uses stable block IDs, announces position and focuses the moved block heading after DOM update. CSS uses existing tokens, wrapping controls, one-column links below 540px, bounded JSON wrapping, visible focus and at least 44px buttons/inputs. The component is designed for 360px; real keyboard, layout, axe and physical-device acceptance has **not** run because the parent's browser Block remains in force. Source rendering/build checks are not that acceptance.

Saving creates one in-memory command. Concurrent clicks share its promise. Network/server failures or malformed success receipts leave outcome uncertain and freeze editing/discard/version-refresh until exact retry resolves. Retry retains key/body/original If-Match; injected transport receives a detached copy. A successful receipt must match document, original body and next document version. Historical replay's original ETag is retained even if another editor subsequently advanced the document; a later stale save follows normal 412 recovery. Known server rejections retain content. Conflict requires an explicit current-version read, preserving unsaved fields and selected revision, followed by human review/save. There is no automatic overwrite, publication or rollback.

Wire `onDirty` into the root navigation/service-worker update guard; dirty content also attaches the ordinary beforeunload guard. Do not remount/drop a controller with dirty or uncertain content during routine navigation/update. All content and commands stay in memory; offline writes are disabled and no browser storage or service-worker private cache is used. Root must call `controller.revoke()` before session/org/document rebinding, membership/capability denial or logout, unmount this feature and clear its supplied history/metadata. Queued commands are cancelled, late responses cannot refill content and denied access cannot retry. Root must not reuse that controller for another binding.

`openRecovery(revisionId, documentId, originalJson)` accepts only an already-authorized matching-document payload. Unsupported JSON is bounded, detached, preserved, escaped in a read-only preformatted panel and never converted to editable content. A future block kind must reach this method through a reviewed recovery reader. Proposal checkpoint `5946c4a` defines the closed local HTTP envelope; no recovery fetch, contract widening or route is implemented here. Future-kind history discovery remains separately unresolved.
