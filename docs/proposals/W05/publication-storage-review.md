## Bounded synthetic namespace correction

Proposed exact SQL entry point: `cms_synthetic_namespace_command(hostname text, action text, expected_generation bigint, domain_id uuid DEFAULT NULL, expected_domain_version bigint DEFAULT NULL, valid_for_seconds integer DEFAULT 30)` returns only generation/binding UUID/enabled. Actions are bind/detach. No tenant/actor/binding UUID/absolute expiry is a caller authority parameter. Bind resolves tenant/site from the exact CURRENT site_domain ID+canonical hostname under a retained SHARE lock and compares current row_version. TTL is 1–300 seconds, starts after lock waits/source authorization, and is checked again before return. IDNA/parser equivalence, fixture environment/TLS interpretation, operator authority and current source clock are still the hosting source owner's prerequisite; `cms_synthetic_namespace_source_allowed` is explicitly false, and false **or NULL** denies. No production evidence is recognized or emitted.

Every namespace-dependent command/read/source writer must use this host prefix: **platform advisory namespace key → permanent counter row → current head row or protected absent slot → exact current domain row**, followed by other source/member/profile/site/document/policy/job locks in root's reviewed order. The advisory key is derived from the canonical host, independent of tenant; hash collision only adds serialization. Bootstrap INSERT/unique-index locks occur after that advisory key. Public/prepare reads use SHARE modes in the same order; mutation takes counter/head UPDATE before domain SHARE/UPDATE. A command touching multiple registered names is not offered here; a future owner must lock canonical names in sorted order before any head/domain tuple. Registered hostname UPDATE is rejected; use separate detach/domain source/new binding commands.

Current `withTenantTransaction` takes membership/role/organization locks before operations, so it cannot simply wrap this new host prefix without a cross-service deadlock review. Future hosted consumers need root-approved coordination that reads tentative identity/metadata without retained source locks, then takes the host prefix and repeats current authorization under locks. Do not resolve a changed tenant after a wait by retaining the old tenant's source locks and adding the new tenant's locks; abort/restart the transaction. Ordinary draft operations that never touch the host prefix remain separate.

The SQL command locks the counter then head then domain, authorizes current sources, compares expected generation/current head, and rejects exhaustion **before** adding one. It mints a private permit, advances the counter, creates a new globally unique immutable binding for bind, then inserts/replaces the head; detach advances the counter and deletes the head, preserving counter/history. Both fail atomically on any source/constraint/trigger error. A deleted head cannot be recreated from an old binding, reenabled at its old generation, or moved A→B→A using a historical UUID. Rebinding even the same current domain creates a fresh generation/UUID. Source deletion, reassignment or version/hostname/site changes never make an old captured domain identity valid again.

Counter/binding/head guards validate only private same-backend/transaction/role permits and **plain nonlocking reads** of the already held prefix. PostgreSQL UPDATE/DELETE has already acquired its tuple lock before a row trigger: acquiring counter/domain locks inside a head/domain trigger would invert the order. The proposed guards therefore reject missing/expired/replayed permits without attempting the prefix. Their only write is to this transaction's own private permit row, consumed by head/source mutation and deleted by the owner command. Binding INSERT also requires a fresh checked tuple/counter; historical versions remain immutable. Truncate/counter reset and direct registered-domain writes deny.

Private permit validity now pairs action with the recorded minter role: bind/detach can be used only by `estate_cms_namespace_owner`, and domain_write only by `estate_cms_domain_source_owner`, matching current_user. The SQL command omits minter_role from INSERT so its default derives from current_user; the future domain source port must likewise derive it internally. Future-dated permits deny. All three head/domain consumption paths require an actual UPDATE of the same unconsumed, still-unexpired private row and check FOUND immediately. Namespace cleanup requires actual deletion of that same consumed row; zero rows raises42501 and rolls back the entire command. SELECT visibility is insufficient: UPDATE/DELETE USING policies can silently filter a row. The future permit owner policies must support both the unconsumed transition and the consumed cleanup state, with exact backend/xid/nonce/role scope. These checks add no counter/head/domain locks or grants. [PostgreSQL 17 policy filtering](https://www.postgresql.org/docs/17/sql-createpolicy.html), [PL/pgSQL FOUND](https://www.postgresql.org/docs/17/plpgsql-statements.html).

The native domain guard recognizes the reserved `example.test`/`.example.test` suffix directly from OLD/NEW, before querying any RLS-protected registration. Every fixture domain, including an unregistered one, requires a separately reviewed domain owner's `domain_write` permit after the same prefix and after explicit detach. A missing/hidden counter or missing permit denies; it cannot count as an unregistered domain and bypass the guard. No extra lookup owner, positive directory policy or runtime/worker/public table grant is introduced. The domain owner must bootstrap the permanent counter before the first fixture-domain INSERT, retain/prove counter/head visibility and absent head, then stamp a permit for one exact source write. The guard enforces ID/tenant/site/hostname identity, an UPDATE row_version successor, absent head and a newly consumed namespace generation. **That domain-write command/permit minting port is not implemented here**; do not activate native fixture-domain triggers/reassignment until root supplies and probes it. Nonfixture domain DML does not use this suffix guard; it remains subject to existing native authority. No direct UPDATE/DELETE/native grants are proposed to namespace bind/detach callers.

Current readers/executors must compare head generation with the durable counter and the immutable binding, then check exact current domain identity/version/hostname/site and current expiry after waits. Old job/preparation/public capsules tied to an earlier generation fail even if tenant/site/domain ID returns to the same values. A retired/absent head returns no public content; expiry never refreshes history. Generation exhaustion at 9,007,199,254,740,991 and native-domain UPDATE version exhaustion deny with SQLSTATE55000 and no partial counter/head/history effect. Stale CAS/source mismatch uses40001; unknown/missing authorization or permit uses42501; malformed command uses22023. None returns private domain/tenant/profile details.

## Anonymous context and least privilege

No anonymous caller can supply org/site/revision/release IDs, set a tenant GUC to gain native access, borrow staff context or reuse an old release URL. The public entry point accepts canonical authority/path only. Validate exact ASCII HTTPS fixture authority and path; reject userinfo, ports, normalization ambiguities, repeated/spoofed/forwarded headers and reserved routes. Only an explicitly configured gateway determines which proxy header, if any, is trusted; headers do not become a routing directory. Browser Block remains in effect.

The resolver clears legacy actor/tenant/session/support and prior public context at entry. An owner-only exact-host helper scopes its directory lookup to the normalized authority; no listing function, arbitrary-org query, `USING(true)` directory policy or table grant to public exists. Acquire the namespace/counter→head→domain prefix in SHARE order before other retained source locks. Under a locked matching current binding/generation/counter/domain, mint a `public_lookup` capsule with derived tenant/site/route/binding and a short expiry. This permits **only** matching active-route and completed-release metadata, avoiding a bootstrap cycle where the release ID is needed to look it up. It permits no prepared HTML/body read.

After resolving those IDs, the narrow source owner checks current organization active, unexpired websites, real profile eligibility, site published/non-suspended, non-archived document, binding/domain/head version and current non-retired policy. Hold source locks, recheck clock after waits, then advance that private capsule to `public` with exact release/prepared IDs and validity bounded by all source expiries. Projection RLS authorizes only that active eligible tuple. Read the bounded HTML/SEO, recheck clock/current binding after the last wait before return, delete the capsule and clear context. Generic404/unavailable on any missing/stale/unknown dependency, including conditional requests; no old snapshot fallback. Pool return/error/rollback clears context; owner-only bounded cleanup removes exceptional committed expired capsules. GUC nonce and backend/transaction IDs are selectors, not authority without an unforgeable private row.

Public visibility does not depend on a former initiating employee remaining a publisher after a successful release. That revocation denies pending execution; current organization/profile/website/host/policy/rights retirement denies subsequent public reads. Unsupported media/form/MLS/social references never acquire an eligibility resolver in this slice. Keep no-store, nosniff, no-referrer and exact renderer CSP; workspace SW/customer HTML cache/ISR/CDN and navigation/sitemap expansion remain absent.

Prospective roles below are logical owner names, **not created or altered here**. Every function owner must be non-login, non-table-owner, NOBYPASSRLS, NOSUPERUSER, with no membership grant to runtime/worker/public and fixed qualified search_path including pg_temp last. EXECUTE defaults must be revoked before any grant. PostgreSQL permissive policies combine with OR; restrictive policies and forced RLS must enforce the capsule/current gates for these owners rather than adding a broad tenant policy. [PostgreSQL 17 RLS](https://www.postgresql.org/docs/17/ddl-rowsecurity.html), [safe definer functions](https://www.postgresql.org/docs/17/sql-createfunction.html).
