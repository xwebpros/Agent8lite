Inspected the integrated root at `b374274b4620935bbce210f69d46f12902cc1971`, migrations 0001–0018, CMS repository/profile reference, tenant transaction/entitlement guards, requester-only administration jobs, frozen contracts/events, `publication-boundary.md` and ADR-024. FKs enforce identity, not permissions or canonical content validity. The source port must compare native revision.content_hash and rerender it with the current pinned policy; SQL bounds/digests cannot sanitize an arbitrary HTML/SEO row. Stored snapshot_hash covers the complete `PreparedCmsPublicationV1` projection in canonical form, including headers/target/title/SEO/version fields. Immutable triggers reject row update/delete and statement truncate; application roles receive no such privileges. This is a DML guarantee, not protection against a trusted migration owner deliberately changing DDL.

`expected_site_version` is captured in the immutable command and rechecked at execution even though the frozen request exposes only expectedDocumentVersion. Require representable document/site successors; do not clamp legacy bigints. A changed theme/profile binding/site version makes the command fail safely. The approved content-only rollback uses current reviewed title/route/theme with the selected revision's blocks/SEO; canonicalPath must match. Its internal rollback_source_release_id must reference an earlier completed publication of that same site/document/revision, not arbitrary private revision history. It is proof of historical publication, never current rights or a request to restore that release's old metadata.

## Acceptance, fencing and current clock

1. In the existing verified caller transaction, hold current member/role/organization/capability/profile/site/document and relevant policy/binding locks in a reviewed common order. Acquire operation/member/document idempotency serialization; recheck current sources and `clock_timestamp()` after every blocking wait. Exact accepted replay first reauthorizes current source access, then returns the original queued **202 Job** receipt before checking its now-old expected version. Changed operation/revision/body conflicts. No mandatory If-Match header is added.
2. A new acceptance validates matching immutable revision/hash, exact current metadata/theme/target/policy, expected versions and rollback proof. Insert queued foundation job, immutable command, private preparation, acceptance audit and durable original response receipt atomically. Acceptance changes no public route, document/site version or publication state. Roll back everything on receipt/audit/job/preparation failure.
3. Discovery uses an explicitly configured trusted worker context and bound stored jobs; a queue message/tenant UUID identifies work but grants nothing. A short claim transaction locks only its job/claim, increments fence and attempt, assigns bounded lease/holder and commits. It does not grant execution. Resolve initiating actor against current active membership, role, organization and organization-scoped content.publish; do not deserialize captured grants. Durable work follows current member authority, not continued browser-cookie lifetime.
4. Execute with current source locks in the common order, then lock job/claim and compare fence/holder/lease/version after all waits. Recheck current actor, websites expiry, public profile eligibility, site/document availability, exact current binding generation/domain version, current policy and both expected versions. Rerender and compare the complete immutable preparation; no remote work while locks are held. Lease must remain unexpired at the final write/return, not merely at claim or transaction start.
5. In one visibility transaction, insert completed release, CAS document V→V+1/published revision through the CMS owner, update site state/time/version through that owner, increment separate publication generation, replace only this document's route, insert audited `site.published` and mark the bound job succeeded through its owner. Insert the release before the route; renamed old route returns generic404. One unique job completion resolves a lost acknowledgment; retry never increments generation again. Two V commands or draft/publication races have one winner. On any failure retain the prior public page; never set a published site to publishing while queued.

Job kind/requester/connection/id/createdAt/command binding must become immutable under a foundation-owned trigger/restrictive policy, including attempted insertion of an unbound CMS kind. Existing `tenant_scope` alone and runtime's billing-related job UPDATE privilege do not enforce this. CMS transitions are allowed only through exact owner ports with the private current command/execution capsule; unrelated kinds keep their existing behavior. Minimal worker API is opaque claim/finalize for its eligible bound job, not arbitrary row updates. Every scope/version/lease/current-time failure has a safe closed outcome and no public effect; unreviewed safe_error values remain generic through the existing Job model.

## Anonymous context and least privilege

No anonymous caller can supply org/site/revision/release IDs, set a tenant GUC to gain native access, borrow staff context or reuse an old release URL. The public entry point accepts canonical authority/path only. Validate exact ASCII HTTPS fixture authority and path; reject userinfo, ports, normalization ambiguities, repeated/spoofed/forwarded headers and reserved routes. Only an explicitly configured gateway determines which proxy header, if any, is trusted; headers do not become a routing directory. Browser Block remains in effect.

The resolver clears legacy actor/tenant/session/support and prior public context at entry. An owner-only exact-host helper scopes its directory lookup to the normalized authority; no listing function, arbitrary-org query, `USING(true)` directory policy or table grant to public exists. Under a locked matching current binding, mint a `public_lookup` capsule with derived tenant/site/route/binding and a short expiry. This permits **only** matching active-route and completed-release metadata, avoiding a bootstrap cycle where the release ID is needed to look it up. It permits no prepared HTML/body read.

After resolving those IDs, the narrow source owner checks current organization active, unexpired websites, real profile eligibility, site published/non-suspended, non-archived document, binding/domain/head version and current non-retired policy. Hold source locks, recheck clock after waits, then advance that private capsule to `public` with exact release/prepared IDs and validity bounded by all source expiries. Projection RLS authorizes only that active eligible tuple. Read the bounded HTML/SEO, recheck clock/current binding after the last wait before return, delete the capsule and clear context. Generic404/unavailable on any missing/stale/unknown dependency, including conditional requests; no old snapshot fallback. Pool return/error/rollback clears context; owner-only bounded cleanup removes exceptional committed expired capsules. GUC nonce and backend/transaction IDs are selectors, not authority without an unforgeable private row.

Public visibility does not depend on a former initiating employee remaining a publisher after a successful release. That revocation denies pending execution; current organization/profile/website/host/policy/rights retirement denies subsequent public reads. Unsupported media/form/MLS/social references never acquire an eligibility resolver in this slice. Keep no-store, nosniff, no-referrer and exact renderer CSP; workspace SW/customer HTML cache/ISR/CDN and navigation/sitemap expansion remain absent.

Prospective roles below are logical owner names, **not created or altered here**. Every function owner must be non-login, non-table-owner, NOBYPASSRLS, NOSUPERUSER, with no membership grant to runtime/worker/public and fixed qualified search_path including pg_temp last. EXECUTE defaults must be revoked before any grant. PostgreSQL permissive policies combine with OR; restrictive policies and forced RLS must enforce the capsule/current gates for these owners rather than adding a broad tenant policy. [PostgreSQL 17 RLS](https://www.postgresql.org/docs/17/ddl-rowsecurity.html), [safe definer functions](https://www.postgresql.org/docs/17/sql-createfunction.html).

Do not grant public SELECT or widen/replace existing author policies. Source and lookup roles must have positive narrowly scoped policies as well as restrictive checks: a restrictive-only policy cannot open default-deny tables. Avoid recursive route/release/context RLS helpers; the lookup phase uses separate owner-only exact-row primitives, and HTML is accessible only in the final phase.

## Expand, backfill and activation

Root allocates a forward sequence after the actual current chain (0018 at inspection; the coordinator subsequently reported integrating marketing0019), never reuse the earlier proposal's obsolete 0017 suggestion. Preflight equivalent unique constraints, existing identity/job data, safe version limits, canonical host collisions and index/lock costs before promotion. Large installations may require concurrent index creation/attachment and NOT VALID FK/validation stages outside one blocking migration; root chooses that plan. No body/hash/history mutation or global tenant/hostname normalization by guesswork.

Empty new tables/default-deny RLS preserve old drafts, revision recovery/history, job kinds and private document/site versions. Do not infer releases from old published_revision_id/site state, copy all drafts to prepared storage, fabricate prior rollback proof or mark every profile/host eligible. Existing pages, if any, need a separately authorized source-verifying adoption job; until then the new resolver has no route. Bootstrap counters/current policy for an explicitly authorized fixture only; counters do not decrement, and source changes remain normal versioned operations.

Promote in stages: storage/immutable constraints with ports still closed; exact owner service contracts/functions/grants plus actual-role source/clock/fence tests; atomic publish/rollback API/job execution; then isolated synthetic public resolver probes. Public routes/hosting stay unregistered until root explicitly promotes them. No credential, provider, DNS/TLS or live Trestle work is included.
