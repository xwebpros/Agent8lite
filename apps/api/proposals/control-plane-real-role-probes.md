# Proposed pre-consumer control-plane database probes

The coordinator authorized candidate-only execution before shared commit, exclusively in a disposable PostgreSQL/PostGIS database under actual separate login credentials. Database probe-group evidence is in control-plane-verification.json; consumer-level assertions remain pending until implementation. Seed unrelated identities, active administrator/support staff, organizations A/B, two grants, and an owned provisioning Job only through the migration identity or reviewed issuer. Never print passwords, session/CSRF bytes, token hashes, reasons, provider configuration or raw PostgreSQL errors.

## Role and issuance separation

1. Call assertRuntimeRole for estate_control and estate_staff_issuer; verify NOSUPERUSER/NOBYPASSRLS, no application relation ownership and no privileged reachable ancestry. Query recursive pg_auth_members closure, including NOINHERIT edges, to prove bidirectional control↔runtime/worker isolation and every issuer crossing; NOINHERIT must not permit bypass via SET ROLE. Reject a configured pool whose current/session login differs from the expected role even when both roles satisfy the generic non-owner invariant. Probe direct and multi-hop control→runtime/worker plus control↔issuer and issuer→runtime/worker memberships using only the verifier's control/issuer login roles as recipients, then restore/delete tracked probe memberships/roles. Existing runtime/worker roles must not acquire new authority during these cluster-global membership probes.
2. With a real estate_control connection and no valid session, set app.actor_id to the administrator, app.auth_issuer/subject to its synthetic verified claims, and attacker-chosen staff_session_hash. Direct INSERT into staff_session must fail with SQLSTATE 42501. Runtime/worker INSERT must also fail. Control may not change an existing session's token hash, user, CSRF, provenance, created_at or expires_at. Setting actor, tenant, support grant or provision claim cannot authenticate an unauthenticated control connection.
3. With estate_staff_issuer, exact verified issuer/subject resolves only that identity's allowed columns. Missing/mismatched claims return no identity; an unverified email identity returns none. The account ID does not come from a browser body. The issuer can lock the corresponding active principal FOR SHARE and insert only issuance columns without RETURNING. Missing actor, actor/claim mismatch, inactive/non-staff identity, supplied support selection, creation over five seconds in the future or over thirty seconds old, and expiry over eight hours must fail closed. Session SELECT/UPDATE/DELETE, staff permission_codes SELECT, tenant/control Job/grant/organization reads and control helper invocation must fail with 42501.
4. Issuer active-principal FOR SHARE blocks a concurrent administrative deactivation until issuance commits. After deactivation commits, control resolution of that retained session must fail. Conversely, deactivation before issuer resolution must prevent INSERT. Wrong issuer pool credentials or missing synthetic mode must fail before any session is inserted.

## Missing context, forgery and current authority

5. Control connection without session hash sees no organization/control Job/idempotency/customer rows and cannot create organization, Job, grant, audit or outbox rows. Set a real administrator actor with an absent/unknown/another-principal session hash: control_authorized is false. A support session plus administrator actor remains false. Malformed context selectors must not produce a successful authorization; the API must map any database parsing failure to a fixed safe Problem without query or credential reflection.
6. Insert a genuine session with issuer and authenticate control using its exact hash/current actor. Platform metadata becomes visible only with its current catalog code. Remove that code with the migration identity: current permission-dependent command/metadata read and idempotent command replay deny even though the session still exists. Restore the tracked fixture. Disable the current principal, expire the session or delete it through authenticated logout: all control helpers return false and customer reads return none. Cached VerifiedStaffContext/SupportReadContext values cannot override this result.
7. Reuse the same pooled connection after COMMIT and ROLLBACK. Without newly verified transaction-local actor/hash/tenant/grant/claim, no previous staff or customer authority remains. A member session never opens a platform context. A staff session does not create membership, and both session types presented to a customer route are rejected until an explicit context is selected rather than combined.

## Support grants and immutable bindings

8. No selected grant means no CRM rows even after app.tenant_id is set. A selected grant for A plus tenant B, a grant belonging to another recipient, an absent/legacy grant with missing issuer/provenance, or a synthetic grant under disabled local mode denies. An active support grant's table reads intersect the explicit allowlist and related contact/lead permission prerequisites. Contact/lead/task/deal/tag writes, notes, exports, consent changes and capability-state updates fail with 42501. Provider secret_ref/safe_config and audit safe_diff remain unselectable even to an administrator.
9. Setting a different grant GUC without matching staff_session selection denies. Revoke/expire the selected grant or deactivate its recipient: current control_grant_allows returns false, all source projections deny, and stale customer list cursor/current-context replay cannot return private data. Expired/revoked grant-command replay may return its historical Job only after current issuing permission is rechecked; it does not change expires_at/revoked_at, reselect the grant or issue another grant. A changed canonical request under the same key conflicts.
10. Hold principal/session/grant SHARE locks in the documented deterministic order. Verify actual concurrent principal deactivation, logout/session deletion and grant revocation wait until a source-read transaction ends. Source reader rechecks expiry immediately before completion using database time, and rolls back audit/output if it expired during work. A separate unlocked stale context must deny after the revoking transaction commits. The narrow recipient helper returns only a boolean, denies PUBLIC/runtime/worker/issuer invocation, and refuses direct calls whose session_user is not estate_control.

## Provisioning claim and atomic completion

11. Only an authenticated authorized principal may INSERT an organization with status provisioning and its owned Job. A fabricated tenant/claim, other principal's Job, queued/failed Job, wrong claim, missing lease or expired lease makes control_can_seed false; default-table INSERT and organization activation fail. Runtime/worker/issuer cannot claim control Jobs or seed defaults through this boundary. Organization writes cannot change another active tenant or unrelated columns.
12. Lock the owned Job for execution, set its verified tenant/claim locally and use a lease that expires during the transaction. After expiry, control_can_seed must become false in the same transaction because it uses clock_timestamp, not transaction-start now. Default INSERT or activation then fails and all module seed rows, audit/outbox and activation roll back. Application execution must separately recheck current staff session/principal/owner-policy and lease immediately before organization activation and Job completion; no success may be persisted by a stale executor.
13. Claim takeover replaces claim_id. The old claim cannot seed, activate or complete; conditional completion/failure compares exact owned Job/claim/revision and never overwrites a newer claim. An authorized retry of a queued/expired lease Job uses stable IDs and creates one Owner/default set; caller rollback, seed exception, lost permission/session, owner identity change or policy mismatch leaves no partial defaults and organization provisioning. Fixed safe failure persistence is a separate verified transaction; no payment/provider acceptance activates it.
14. In one caller transaction, seed SaaS, CRM and mock billing through their respective transaction-bound ports, then deliberately throw. Query through the migration identity after rollback: no organization activation, Owner/default stages/source/routing/subscription/entitlements, domain outbox or success audit from that attempt. Successful execution commits one non-staff Owner, exact six stages/source/routing, mock policy, one success Job/audit/event. Repeat the exact durable command/claim recovery and prove no duplicate organization, defaults or side effects.

## Schema checks before route tests

15. Confirm all three new control tables have ENABLE/FORCE RLS; runtime/worker have no new privileges; immutable control_idempotency cannot be UPDATE/DELETE/TRUNCATEd. Verify new policy role lists do not weaken existing runtime/worker tenant isolation. Verify the identity policy split still supports member session bootstrap, member profile reads, and the approved control owner-policy resolver without allowing issuer tenant access. Verify support issuer/reason/expiry bindings and foreign keys preserve old rows while rejecting them as trusted grants. Migration re-run checksum and fresh 0001–0012 migration/seed must pass before publishing consumer readiness.

After these boundaries pass, add original frozen HTTP-shape, CSRF, local-mode/socket, per-command concurrency/replay and responsive staff-banner tests. No new production identity, worker, billing or MLS activation is implied.
